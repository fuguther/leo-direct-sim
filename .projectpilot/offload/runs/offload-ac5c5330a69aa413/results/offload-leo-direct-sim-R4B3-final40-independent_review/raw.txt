PR #40 Q0 snapshot 整改终审

终判：REQUEST_CHANGES

基于精确 commit f64024c4cffa83a3e5b2fe09d5335e84498c1b46 的允许路径静态审查：

A1：基本闭合。 当前 association 会主动物化 GSL GE；snapshot 对当前 association 及已物化 universe 都显式输出 materialized/bad/next_flip，并存在未物化 fallback。

A2：主体修复，但仍有语义缺口。 三类 server 的 phase 生命周期基本正确，但 _transmit() 在 deadline/TTL race 判定之前就盖章 transmitting，因此“真实传输开始”这一合同仍存在反例；而且 residual 没有 max(0, …)，严格“不可能为负”未机械保证。

A3：仅数据包部分闭合。 ingress/ISL/deliver 三条数据传播路径确实保存 pkt，snapshot 也投影了完整 DataPacket 状态且不返回内核对象；但 ControlPacket 的传播态完全没有进入 _in_flight，queued/in-service control 也只有 iid。这与函数自述的“global current state for Q0”不一致，并且允许文件内没有把 control-in-flight / checkpoint-resume 明确降级为 design follow-up。

因此不是 BLOCK，但当前不应把 Q0 snapshot v1 视为完整闭合。

A1 — GSL GE universe

[FACT] _associate() 已在创建 ep.links[sat] 后立即调用 _gsl_ge(sat, ep.cell)。 在本次允许范围内检查 ep.links 的生产写入口，没有发现第二条直接创建 association 的生产路径；正常 association 因而都会物化对应 GE。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1480-L1490

[FACT] snapshot 的 universe 是 self.gsl_ge ∪ 当前 ep.links，对每个 pair 都输出显式三元状态。 即使某个当前 association 异常绕开 _associate()，仍返回：

materialized=False, bad=None, next_flip=None

而不是静默缺 key。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L970-L989
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/tests/test_q0_snapshot.py#L83-L116

[INFERENCE] 提前物化不应扰动其他 link 的 RNG 流。 _gsl_ge() 使用 seed + "gsl:{sat}:{cell}" 创建 keyed link_stream；允许测试又验证了 GE query-pattern independence 和不同 link 创建顺序不改变各自轨迹。由此可以合理推断 association 时提前创建不会产生全局 RNG 顺序耦合。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1023-L1032
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/tests/test_fates_outage.py#L83-L112

但这里仍有一个证据边界：允许测试只直接覆盖通用 GE/link-stream 性质，没有专门做“旧 lazy materialization vs 新 association materialization”的 GSL 端到端轨迹 diff，见 open_items。

A1 结论：PASS。

A2 — _svc_phase / _tx_started_at / remaining service
正常生命周期已经基本修复

[FACT] Uplink、Downlink、ISL 三类 server 都采用相同模式：

packet 被选中后 _svc_phase="waiting_for_link"、_tx_started_at=None；

调 _transmit(..., owner=self)；

_transmit 返回后，无条件清理 _svc/_svc_phase/_tx_started_at/current；

然后才分派 retired/stalled/fail/ok。

因此对于 _transmit 正常返回的 success/failure/retired/stalled 路径，没有发现某个 outcome branch 在复位前 early-return/continue 而遗留脏 phase。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L307-L318
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L424-L434
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L556-L567

[FACT] waiting_for_link 的 residual 现在返回完整 bits/rate；transmitting 从 _tx_started_at 计算 elapsed。 原先把 down-wait 算作已消耗 service 的大问题已被纠正。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L879-L894

F1 — deadline/TTL 已到仍可短暂盖章 transmitting

严重度：major

[FACT] _transmit() 先进行 geometry/GE/retirement availability 检查，然后立即：

owner._svc_phase = "transmitting"
owner._tx_started_at = t0

但 packet deadline / ControlPacket TTL 是否已经到期，是之后计算 fail_t 时才处理。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1125-L1155

[FACT] Uplink/Downlink 的 deadline sweep 是 ticker 驱动，不是在每次 server dequeue 时同步验证。 因此一个 packet 可以在两次 ticker 之间过期，而前一包又恰好在这个窗口完成，随后过期 packet 被 server 取出。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1219-L1246
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1459-L1469

[INFERENCE] 在这种情况下，expiry < t0 会使后续 wait 成为 timeout(0)，但在这个零时事件完成前 snapshot 可观察到 phase="transmitting"。 实际没有任何有效传输窗口，所以这违反了整改要求中的“盖章位置必须是真实传输开始”。

建议把 already-due expiry/TTL 判定放在 phase stamp 前，或者先完整算出 race，只有确认存在 fail_t > t0 的真实 service interval 后才盖 transmitting。

DataPacket 部分已经修复

[FACT] 三个数据传播 producer 均把真实 pkt 保存在内核 _in_flight：

uplink → ingress；

ISL → next satellite；

downlink → deliver。

F3 — ControlPacket 传播态仍从“global current state”中消失

严重度：major

这是本轮最明显的 A3 遗留。

[FACT] ISL data packet 完成 service 时进入 _in_flight；ControlPacket 完成同一 ISL service 后却直接启动 _ctrl_arrive_after_prop()，没有任何 tracker 写入。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L578-L590

[FACT] _ctrl_arrive_after_prop() 直到传播延迟结束才重新出现于内核逻辑；传播期间 snapshot 无对应状态。

证据：
github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1418-L1445

这意味着某个 snapshot 时刻可能存在一个将于未来 t+Δ 更新控制 cache 的真实 packet，但 snapshot 不包含它。对于依赖未来控制 cache 演化的 centralized planner，这不是完整的当前 Markov state。

isl_links 中：

ctrl_q 是 iid 数组；

control in_service 只有 {"iid": ...}。

没有 origin/seq/generated_at/ttl_s/remaining_hops/payload_bits 等决定 expiry、转发及未来 cache 更新的信息。

合并前建议

修 _transmit()：把 already-due deadline/TTL 判断和 race 决定放在 transmitting 盖章之前；只有确实存在正长度 transmission interval 才设置 _tx_started_at。

若 remaining_service_s >= 0 是接口 invariant，返回 max(0.0, calculated_remaining)，并加 exact-completion 测试。

为 ControlPacket 建立 namespaced control_in_flight 或统一 propagation tracker；至少输出 iid/origin/seq/generated_at/ttl_s/remaining_hops/payload_bits/from/to/arrival_at。

同样补全 queued/in-service control projection；否则 centralized Q0 无法从当前状态推导 control expiry/cache arrival。

如果 v1 明确不承诺这些内容，必须修改 snapshot_global() 合同，显式列出 control propagation 和 full checkpoint/resume 为未覆盖的 design follow-up，不能继续写成无条件 “global current state”。

加真实事件驱动测试：Uplink/Downlink/ISL 的 wait→tx、success/fail/retired/stalled、expired-before-start，以及 snapshot mutation-isolation；ControlPacket 要在真正 propagation 中抓 snapshot，而不是只测试“不 crash”。

本地 Agent 需要实际运行允许范围测试；本 Worker 按任务合同未执行本地 Shell，因此当前结果只能是 RESULT_CANDIDATE。
