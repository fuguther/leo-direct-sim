## 六个指定问题的回答

### 1) finalization/artifact hash 是否充分绑定 analyzer 与两臂包？——两臂包：是；analyzer：否（BLOCKER F1）

- 两臂包绑定充分：`finalize_decision.py` 对 decision 声明的每个 artifact 重算 sha256（`CODE/work/finalize_decision.py#L113-L120`），每个 review receipt 必须绑定全部 decided artifacts（`#L184-L186`）；`authorize_experiment.py` 要求 finalization 的 artifact_hashes 覆盖当前实验全部编译产物（`CODE/experiment_platform/authorize_experiment.py#L416-L426`），该集合含两臂 resolved 配置（`EXPERIMENTS/EXP-20260824-ISL-BANDWIDTH-PILOT-R01/compile-report.json#L2-L9`）。
- **analyzer 无绑定**：`run-manifest.json` 的 `execution_chain_sha256` 只含 authorize/deployment_guard/remote_job/run-remote 四个执行链文件（`EXPERIMENTS/EXP-20260824-ISL-BANDWIDTH-PILOT-R01/run-manifest.json#L49-L54`）；`v2_analysis.analyze()` 的 inputs 只绑定结果 artifacts（`CODE/experiment_platform/v2_analysis.py#L380-L386`），输出 manifest 无任何 analyzer commit/hash 字段（`#L387-L406`）；`verify_persisted_analysis` 用"当前检出的代码"重算而非对照固定 commit（`#L479-L490`）。而 brief 验收明确要求 "binds the analyzer's exact Git commit"（`CODE/work/WP-LEO-V2-ISL-BANDWIDTH-PILOT/R01/brief.json#L51`）。**被篡改或漂移的 `v2_analysis.py`/`metrics.py` 可以产出 VERIFIED 结果而无任何已审计 hash 能发现。**

### 2) authorization 在 merge 后是否仍可校验？——是，设计为重算式，merge 不失效

`verify_authorization` 不依赖 git 状态：重跑 `evaluate_decision`（`CODE/experiment_platform/authorize_experiment.py#L77-L81`）、全量重建 payload 并精确比对（`#L464-L490`）；发射时 `verify_authorization_for_leo_sim_v2_config` 还把 config 路径、`code_sha256`、`execution_chain_sha256` 与当前部署代码重新绑定（`#L514-L544`）。只要被绑定文件内容不变，merge 后校验等价成立；任何文件变动 fail-closed。注意 matrix 分支的具体校验委托给 `CODE/leo_sim/matrix.py`（`#L233-L249`），该文件不在允许读取路径内，无法确认其检查集（OPEN_ITEM 1）。

### 3) 远程脚本如何安全选择 clean checkout 且不复制/泄露 remote.env？

- clean 选择：`push-remote.sh` 拒绝脏树、要求 40 位 hex commit（`CODE/scripts/remote/push-remote.sh#L27-L33`），经 `deployment_guard.py build` 打包并在远端 staging 校验后 install（`#L35-L59`）。
- remote.env 仅本地 `source`（`CODE/scripts/remote/common.sh#L7-L26`），不进入任何显式传输参数；仅 `REMOTE_ENV_ACTIVATE` 作为激活命令嵌入远端命令串发给目标主机（`CODE/scripts/remote/run-remote.sh#L152-L158`），属设计内。
- `run-remote.sh` 把 config/authorization 限制在 `EXPERIMENTS/` 内、拒绝符号链接、本地算 hash+nonce 并作为 expected 值交给远端任务（`CODE/scripts/remote/run-remote.sh#L59-L134`），禁止任意命令（`#L43`）。
- **未能闭环**：部署包是否排除 `remote.env`、是否强制 main 分支/与 origin 对账，都在 `deployment_guard.py` 内（允许路径外，OPEN_ITEM 3）。

### 4) 两臂顺序运行与自然结束检查是否有遗漏？——有遗漏

- 无任何机制强制两臂顺序/独占执行；`--exclusive-simulation` 只检查旧平台 `SimulationRL.py` 进程（`CODE/scripts/remote/run-remote.sh#L163`），不阻止两个 V2 tmux 会话并发。离散事件结果不受 wall-clock 争用影响，但这偏离了"同一 clean 部署上受控顺序执行"的表述；远端部署回执与授权的再校验在 `remote_job.py`（允许路径外，OPEN_ITEM 4）。
- 自然结束：分析侧可见的闸门是外部 witness 的 `status==success`+`exit_code==0`、nonce/授权/results 目录身份绑定（`CODE/experiment_platform/v2_analysis.py#L105-L132`）、governance receipt 的 `research_eligible is True` 且 `verification_errors == []`（`#L232-L234`）、以及 `receipt_mod.verify_receipt_dir`（`#L202-L205`）。但 `max_events=20000000`（`EXPERIMENTS/EXP-20260824-ISL-BANDWIDTH-PILOT-R01/request.json#L135-L141`）触顶停止与"自然结束"的区分、zero-rate hold 检测都在 `receipt.py`（允许路径外，OPEN_ITEM 2）。**已审计代码中没有一处显式检查 stop/end reason 字段。**
- 正面：缺臂/败臂会 fail-closed——cohort 必须精确等于计划集（`CODE/experiment_platform/v2_analysis.py#L351-L365`），符合 brief "stops analysis rather than being silently excluded"（`CODE/work/WP-LEO-V2-ISL-BANDWIDTH-PILOT/R01/brief.json#L52`）。

### 5) paired analysis 前必须验证的字段（已在代码中落实 / 缺失）

已落实：receipt 目录验证（`CODE/experiment_platform/v2_analysis.py#L202-L205`）、receipt schema 分支与 v3/v4 隔离（`#L220-L231`）、`receipt.config_sha256 == 授权值`（`#L241-L242`）、receipt hash 被 formal+governance 双 witness 绑定（`#L237-L240`）、governance witness 绑定 trace_manifest schema/identity contract/hash（`#L243-L253`）、外部 witness 五字段重复绑定（`#L33-L36, L126-L131`）；分母语义由 `metrics.py` 保证：service window `capacity == rate×time`、served ≤ capacity（`CODE/leo_sim/metrics.py#L262-L281`）、可用容量采样窗校验且去重（`#L299-L317`）、`utilization = served_bits / 采样 available_capacity_bits` 并 clamp 到 1.0（`#L331-L342`）、分析侧按 `stage=="isl"` 过滤且无 ISL 链即报错（`CODE/experiment_platform/v2_analysis.py#L180-L187`）。

### 6) primary metric 不能被误称为什么

`isl_link_utilization_max` = 每条有向 ISL 链在整个 horizon 上 `served_bits / 采样 available_capacity_bits` 后的跨链最大值（`CODE/leo_sim/metrics.py#L331-L342` + `CODE/experiment_platform/v2_analysis.py#L180-L187`）。它**不是**：1 秒窗口/瞬时峰值（`brief.json#L13`）；纯容量倍增效应（`brief.json#L12`、`request.json#L92`）；因果/算法/论文级效应或阈值（`brief.json#L38-L46`）；均值指标；数据面 goodput 比——分子是该链全部 served bits（已审计代码无控制/数据类别过滤，`CODE/leo_sim/metrics.py#L272-L294`），分母是采样可用容量且 clamp 到 1.0。
