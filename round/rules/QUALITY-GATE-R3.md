# 质量闸门与循环控制（QUALITY-GATE-R3，2026-09-11 合并版）

> 本文件 = 原 `QUALITY-GATE-R2.md`（G1–G5 判据 + 致命项）与 `LOOP-CONTROLLER.md`（循环、并行度、终止条件、材料清单）的**合并版**。
> 合并原因：两者都定义"轮次上限"，分散在两处导致口径不一致（R5 体检发现）。
> **两级轮次的区别（本节为唯一权威）**：
> - **卡级轮次**：单张卡的"深化→审查→修订→复审"循环，≤3 轮，超限淘汰该卡（见 §3）；
> - **轮级（Round）**：整个选题循环的轮次，≤3 轮，超限触发如实报告（见 §5）。
> 两级独立计数；卡级计数由 `round/tools/gate_rounds.py` 硬记录。

## 第一部分：闸门（原 QUALITY-GATE-R2）

## 0. 「走一遍」与「迭代到质量」的判据差别

| | 走一遍（不合格） | 迭代到质量（本文件要求） |
|---|---|---|
| 结束条件 | 流水线步骤跑完 | **每张卡过闸门**，或明确淘汰并说明卡在哪段论证 |
| 失败处理 | 补一节风险声明/加限制条件，保留推荐 | 核心理由失败即**停止维护该版本**，转方向内其他问题 |
| 审查 | 有意见就记录 | 致命项（must-fix）未消除**不得进入推荐** |
| 无合格品时 | 仍凑一条推荐 | 如实报告"无合格主线"+ 卡点 + 下一项可改变决定的信息 |
| 轮次 | 一轮 | 至少一轮修订-复审闭环（每卡 ≤3 轮，超限即淘汰） |

## 1. 五道内容闸门（每张深化卡必过）

**G1 现象成立** — 所声称的"负载变化下现有方法做不好"必须有：
- ≥1 条**【原文事实】**（回原文 PDF，给页码/行号/表号）；且
- ≥1 条**独立第二来源**（不同论文/不同实验合同）或明确标注"单一来源"；且
- 区分【原文实际观察】/【作者解释】/【我的推演】/【待证】四档。
- **不通过**：把"论文没测"写成"论文做不好"；仅凭摘要级信息断言现象。

**G2 原因有依据** — 必须：
- 给出机制链（负载变化 → 什么量改变 → 策略/学习的哪一步失效 → 到达率或时延如何受损）；
- **列出并排除≥1个竞争解释**（不是罗列，是给判据）；
- 通过"跨论文化合"检查：不同论文、不同条件下是否真能支持同一现象（合同可比性）。
- **不通过**：机制缺失、只描述现象、把相关性当因果。

**G3 改动对症** — 拟议改动必须：
- 先指明原因，再选手段（训练覆盖/信息可辨识性/学习更新/奖励/决策结构）；
- 写出**一次具体决策或学习更新**（状态量、动作、目标函数或更新式如何变），说明它如何作用于 G2 的机制；
- **写明失效条件**（什么情况下这个改动不会起作用）；
- 不以模块数/代码量衡量创新。
- **不通过**：改动与原因对不上；或改动无法表述为一次可执行的决策/更新。

**G4 简单办法为何仍不足** — 在信息、训练预算、适用条件**对齐**后逐条比较：
- 普通混合负载训练；合理在线微调；已有可获得信息（不新增观测）；规则路由（阈值/最短路/ELB 类）；直接近邻方法。
- 每条给出"能吃掉多少收益"的判断与理由；**必须存在"尚存困难 + 机制依据"**。
- **不通过**：靠弱化基线创造空间；靠"没有实验所以不知道"回避。

**G5 最近邻差异** — 库内（SOURCES.csv/notes-neutral）+ 外部（Undermind/arXiv/网页）双向核；
- 若无 unresolved 的高重叠对手，或与 TAP-DAR 级对手的差异可明确表述；且
- 相似度只作线索，覆盖判断须比对〔条件/困难/机制/决策变化〕四要素。
- **不通过**：发现直接对手却仅以"我们更聚焦/更通用"了事。

## 2. 独立审查与致命项规则

- 审查者必须是**新子对话**，不得读主控推理链，只拿卡片与证据指针；
- 审查者须逐条判 **PASS / REVISE / KILL** 并对 G1–G5 给出依据；
- **致命项**定义：G1 现象不成立、G2 原因被证伪或不可区分、G4 显示简单办法已足够、G5 存在未处理直接对手。**致命项未消除 → 该卡不得进入推荐**。

## 3. 迭代轮次与终止

- 每卡：深化 → 审查 → 若有 REVISE/KILL → 修订 → 复审；**≤3 轮**。
- 3 轮仍未过闸 → **淘汰该卡**，转向同一研究方向内其他问题（不靠改名/加条件/补风险声明续命）。
- 三路全部淘汰不推翻"负载变化"方向本身。
- 预算内无卡过闸 → 交付**"无合格主线"报告**：卡在哪段论证、已排除什么、下一项信息为何可能改变决定。

## 4. 自我防伪条款（防止我用流程完成冒充选题成功）

- 禁止把"流程跑完/文件齐全/审查有意见"当作通过证据；
- 禁止把"性能收益待验证假设"当作免责声明反复使用——G3/G4 必须给出机制级理由；
- 每轮结束时自问：**这张卡现在比上一版更强，还是只是更长？**若只是更长，回退或淘汰；
- 交付报告中必须单列**未通过项与淘汰原因**，与推荐项同等显著。

## 第二部分：循环控制与材料清单（原 LOOP-CONTROLLER）

> 用户指令（2026-09-10 对齐）：**并行最多 3 个主题**；**不局限于已有 9 卡**，可在 LEO 路由（时延/负载/到达率）小领域内自由选题；
> **直到至少 2 个很好的选题跑完整个流程，各个材料都按老师的准备全**；被刷掉的卡**必须保存理由**。

## 7. 终止条件（唯一的"可以收工"判据）

**当且仅当 ≥2 个主题同时满足下列全部条件**，本轮循环终止：

```
[合格] 该主题通过 G1–G5 全部闸门（无未消除致命项）
[完整] 该主题的"材料清单"（§10）全部齐备
[留痕] 该主题的审查记录、闸门判定表、must-address 回应、证据指针全部落盘
[对比] 与其余保留主题的取舍理由已写明（为何推荐这条/备选那条）
```

**不满足时的默认动作**：继续循环（§9），**不得**以"流程跑完""时间到了""文件齐全"收工。

## 8. 并行度与角色预算

| 阶段 | 并行上限 | 说明 |
|---|---|---|
| 生成 | **3**（= A/B/C 三轴，或按新轴重组） | 每次生成必须全新上下文、互不可见 |
| 深化 | **3** | 每主题一个子代理；超过 3 则排队 |
| 三角色审查 | **3/主题**（builder/neighbor/evidence 各一） | 但可跨主题排队，总投资受 §2 总量控制 |
| 历史审查 | 1（批量审当前池） | 每轮一次，审全部在池卡 |

**总循环轮次上限**：3 轮（与 §3 的每卡 ≤3 轮**独立计算**——卡级计数由 `round/tools/gate_rounds.py` 硬记录）。
3 轮后仍 <2 条合格 → 触发 `EXPLORATION-FALLBACK` §4 的**如实报告**流程。

## 9. 单轮循环（Round N）

```
3.1 生成（≤3 路，全新上下文）
      —— 若本轮是对上一轮的"轴扩展"或"提问类型转换"，在提示词中写明新轴，
         但**不得**把上一轮的候选身份/死因写进生成器提示词（只给论文事实）

3.2 初筛（主控）
      —— 去重、合并同题、登记 ledger（add）
      —— 必跑污染审计 `round/tools/audit_contamination.py`；违规 → 该批作废重跑

3.3 历史碰撞审查（独立子代理，1 个，审全池）
      —— 五类裁决 + must-address 清单

3.4 收窄（主控）
      —— 保留：裁决 ①②③ 且 G1 现象有原文锚点者
      —— 淘汰：裁决 ④ 且致命
      —— **每张被淘汰的卡都写淘汰记录**（类型 A/B/C + 依据 + 是否带复活条件）
         → ELIMINATED-REGISTER §6

3.5 死因回传（主控摘录）
      —— 为每张保留卡写 feedback/<卡ID>.md（仅本卡相关；禁历史全集）

3.6 深化（≤3 并行）
      —— 三问 + must-address 逐条回应 + 承重引文回原文

3.7 三角色审查（各新上下文）

3.8 闸门判定（主控填 GATE-TEMPLATE）
      —— 过 / 修订（≤3 轮）/ 淘汰（写理由）

3.9 若本轮结束时"合格主题数"仍 <2 → 进入 Round N+1（回到 3.1）

3.10 每次循环结束 → 更新台账、提交推送（每轮一个 checkpoint）
```

## 10. 单主题的完整材料清单（"按老师的准备全"）

一个主题要**能直接拿去给老师讲**，必须齐备以下材料。缺任何一项 → 该主题标记"材料不全"，不得计入 §1 的"合格"计数。

### 10.1 论证材料
- [ ] **三问完整回答**（每问须有：结论 + 证据 + 反方检查）
  - 问1：条件、具体方法、训练/部署设置、负载变化形式、影响到达率/时延的过程
  - 问2：原因辨析 → 对应手段 → **一次具体的决策或学习更新**（状态量/动作/目标函数/更新式）→ 失效条件
  - 问3：混合负载训练 / 在线微调 / 已有信息 / 规则路由 / 直接近邻，**对齐条件下**逐条比较
- [ ] **机制图**（Mermaid）：能走通一次决策 + 一次学习更新
- [ ] **承重证据表**：每条断言 → 论文（cite_key/itemKey）+ 节号/表号 + 原句摘录
- [ ] **反证与边界**：已知反例、适用边界、什么情况下本方案不成立

### 10.2 差异材料
- [ ] **最近邻清单**：最接近的 3–5 篇，逐篇写四要素差异（条件/困难/机制/决策变化）
- [ ] **直接对手核查记录**：Undermind `citing` 检索结果 + 结论（是否构成威胁）
- [ ] **查新记录**：patched_novelty 四态 + "未命中"的限定措辞

### 10.3 验证材料
- [ ] **验证设计**：实验矩阵（自变量/因变量/对照）、指标定义、seed 与重复次数、判定阈值
- [ ] **第一步行**（半天–两天）：具体做什么、看什么、什么结果算通过/淘汰
- [ ] **负结果预案**：若首步失败的下一步
- [ ] **基线清单**：每条基线为什么公平（信息/预算/条件对齐说明）

### 10.4 过程材料
- [ ] 闸门判定表（GATE-TEMPLATE 填写版，含每轮）
- [ ] must-address 逐条回应
- [ ] 审查意见与处置记录（采纳/驳回 + 理由）
- [ ] 台账版本链（cand_id → version → content_hash）

### 10.5 汇报材料
- [ ] **一页主报告**：问题、为何值得做、怎么做、与现有工作的差别、预期贡献
- [ ] **完整研究文稿**：场景 → 现有不足 → 原因 → 针对性改动 → 最近邻差异 → 验证设计
- [ ] **文献指引**：先读哪几篇、承重原文位置、阅读顺序建议
- [ ] **取舍记录**：比较过哪些实质不同的问题、什么证据改变判断、为何推荐这条

## 11. 淘汰记录规范（"被刷掉的也要保存理由"）

每张未通过的卡，在 `ELIMINATED-REGISTER.md` §6 追加一行，**必含**：

| 字段 | 内容 |
|---|---|
| cand_id + 标题 | 台账标识 |
| 淘汰类型 | A 证伪/覆盖 / B 流程中止 / C 合并吸收 |
| 淘汰阶段 | 哪一步被刷（初筛/历史审查/深化/闸门 Gx） |
| 依据 | 具体证据或裁决出处（**不得**只写"不够好"） |
| 是否带复活条件 | 若有，写明条件与判据 |
| 与保留主题的关系 | 是否被吸收进某条主线（资产去哪了） |

**禁止**：删除卡文件、清空台账、把淘汰理由写成"暂不考虑"。

## 12. 自我审计（每轮结束时问自己）

1. 本轮新增了**信息**，还是只是把同样的东西换了个说法？（后者 → 触发提问类型转换）
2. 有没有因为"想凑够 2 条"而放宽 G1–G5？（有 → 回退）
3. 被淘汰的卡，理由是否能被第三方复核？（不能 → 补证据）
4. 深化者是否只看过本卡反馈？（不是 → 该卡深化作废重跑）
5. 交付材料是否真能拿去讲给老师？（不能 → 对照 §4 补）
