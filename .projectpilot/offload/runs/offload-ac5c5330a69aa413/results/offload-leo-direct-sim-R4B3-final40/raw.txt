1. A1 — GSL GE universe：PASS
1.1 _associate 已主动 materialize 每个真实 association

FACT

_associate() 创建唯一的 endpoint↔satellite Link 后，立即调用：

self._gsl_ge(sat, ep.cell)

然后才写 slot 和继续 activation，因此正常生产路径创建的 association 不再依赖第一次 transmit/query 才产生 GE。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1480-L1497

完整文件检索中没有发现第二个生产态 Link(...) 创建入口；ISL 使用的是独立 ISLLink 类型。因此，在本文件范围内，所有正常 GSL association 都经过 _associate。

1.2 snapshot universe 不再靠 key absence 表示未实例化

FACT

snapshot_global() 显式定义：

gsl_pairs = set(self.gsl_ge)：所有已经 materialize 的 pair；

再遍历每个当前 ep.links，加入当前 association；

对每个 union pair 均输出记录；

如果没有 GE 实例，明确输出：

materialized=False
bad=None
next_flip=None

而不是静默省略。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L968-L994

这比只枚举 self.gsl_ge 更稳健，即使异常/legacy 路径制造出当前 link 却未 materialize，也不会把“不知道”伪装成“不存在”。

1.3 RNG/确定性风险基本闭合

FACT

GSL GE 使用：

rngmod.link_stream(seed, f"gsl:{sat}:{cell}")

即每个 pair 使用 key 派生的独立 stream，而不是从一个创建顺序相关的共享 RNG 顺序取样。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1017-L1028

允许范围内的 outage 测试还验证了两件与该判断直接相关的性质：

GE observable trajectory 与查询密度无关；

rng.link_stream() 按不同 link key 反序创建仍得到相同 per-link trajectory。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/tests/test_fates_outage.py#L84-L109

INFERENCE

因此，把 GSL GE 的创建时刻从“首次使用”提前到“association”不会因为 pair 创建顺序而扰乱其他 pair 的 RNG stream，也没有证据表明 snapshot 查询频率会改变未来 GE observable trajectory。

1.4 A1 测试

新增测试同时覆盖：

正常 association 后输出 materialized/bad/next_flip；

人工构造“当前 link 但无 GE”的 fallback 必须显式为 materialized=False。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/tests/test_q0_snapshot.py#L84-L116

A1 结论：通过。

FACT

Uplink、Downlink、ISL 全部维护：

_svc

并在选中 packet 时：

_svc_phase = "waiting_for_link"

ISL：github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L543-L568

2.2 真正 transmission start 的盖章位置正确

FACT

_transmit() 在循环中先完成：

geometry-up 检查；

GE-up 检查；

retirement deadline 检查；

down-wait/recovery；

只有确认链路实际能够开始服务后才执行：

owner._svc_phase = "transmitting"
owner._tx_started_at = t0

因此 pre-service down-wait 不会提前设置真正发送开始时间。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L1082-L1137

这是 R4B2 A2 的核心修复。

2.3 正常 return / retired / stalled / failure 后 phase 均先清理

FACT

三个 server 都在 _transmit 返回后、判断 outcome 之前立即：

_svc = None
_svc_phase = None
_tx_started_at = None
current = None

所以 retired、stalled、普通 fail、成功等正常返回路径不存在分支先 continue/break/return 导致 phase 残留的问题。

证据：

Uplink：github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L303-L340

Downlink：github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L421-L452

ISL：github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L552-L580

INFERENCE

对 _transmit() 的所有正常 outcome 而言，没有发现 early-return 绕过 reset 的生产路径。异常导致整个 SimPy process 抛出的情况不属于上述正常-return 保证。

2.4 snapshot residual 现在按 phase 计算

FACT

新的 _remaining_service()：

waiting_for_link → bits/rate，即完整服务时长；

transmitting → bits/rate - (now - tx_started_at)。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L875-L896

因此原来“从取包时间开始扣，down-wait 越久 residual 越小甚至负数”的主要错误已闭合。

不过代码并没有执行 max(0.0, ...)。在正常 SimPy service 生命周期下没有发现能持续跨越真实 completion 后仍保持 transmitting phase 的普通路径，因此没有找到可造成显著负值的正常生产路径；但“never negative by construction”在纯浮点层面仍不是硬约束，数值 epsilon 无 clamp。

FACT

ISL 完成后：

if is_ctrl:
    process(_ctrl_arrive_after_prop(...))

即 data 被追踪，而 control 的 propagation timeout 没有任何 snapshot-visible tracker。

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/tests/test_q0_snapshot.py#L58-L82

DataPacket 内核对象另外保存：

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L66-L86

这些字段并没有进入 _packet_info()。

所以当前 snapshot 可以合理定义成 Q0 planner 所需的物理/data-plane current-state view，但不能称为完整 simulator checkpoint / resume state。

4.5 允许路径内没有看到这个边界被明确写成 follow-up

snapshot_global() 文档反而称其为：

“global state snapshot”

“CURRENT-state only”

证据：

github://fuguther/leo-direct-sim/blob/f64024c4cffa83a3e5b2fe09d5335e84498c1b46/CODE/leo_sim/kernel.py#L835-L848

INFERENCE

这会让后续消费者误以为它已经足够做 simulator-complete state capture。按照本轮验收要求，至少应该明确写出：

若 Q0 v1 明确只要求 centralized data-plane planner state，可以不在本 PR 实现 checkpoint/resume，但必须把边界写清楚。
