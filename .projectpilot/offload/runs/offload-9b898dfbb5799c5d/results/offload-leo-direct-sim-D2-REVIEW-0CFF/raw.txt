RESULT_CANDIDATE verdict：REQUEST_CHANGES

绑定 commit：0cff2547c59ca2d8f66d690f6b922d6bf71588b9

核心结论：当前实现明确采用“queued data 回退 holding、queued control 留在旧 ISL drain、正在 service 的 data/control 不打断”的非对称退役策略；但该策略目前不是物理一致、fail-closed 的。 最严重的问题是：旧 E/W 链路仍有独立服务进程，同时同一方向的新 ISL 立即创建并可开始服务，因此旧 control queue 甚至可以在 rematch 之后才开始传输，造成同一方向单收发机被旧、新两个 peer 并发占用。

1. 退役链路语义：明确，但存在阻塞性矛盾

在 rematch 时实际行为如下：

rematch 时 packet 状态	实现行为	判定
old data_q	popleft() 后转入 pending[s] / holding	有意，不 drain
old ctrl_q	留在旧 ISLLink	有意 drain / TTL expiry
old current data/control service	不移动、不打断	有意继续旧 peer service
已完成 service、正在 propagation	继续原 peer 到达	合理
rematch 后新 traffic	使用新的 self.isls[s][direction]	合理，但会与旧 server 冲突

设计文档也明确规定了这种非对称语义。

F1 — blocking — FACT + INFERENCE

Retired old ISL 与 replacement ISL 可同时使用同一 E/W 方向收发机，控制包甚至可在 rematch 后才在旧 link 开始 service。

FACT

动态 matching 本身规定每颗卫星每个 E/W 方向只有一个匹配槽，并用 used[a]["E"] / used[b]["W"] 强制这一约束：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/model.py#L524-L571

设计也明确写的是“两端 E/W 收发机方向槽尚未占用”：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L40-L48

但 rematch 时：

旧 link 的 data_q 被迁走；

ctrl_q 与 current 不动；

旧 link 被放入 _retired_isls；

同一 direction 的新 ISLLink 立即实例化。

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L955-L980

而每个 ISLLink 都拥有自己的独立 _run() process；没有 retired/draining 状态阻止旧 link 再 dequeue control，available_now() 只检查 GE 和旧 peer 的几何可用性：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L559-L657

INFERENCE / reproduction condition

令 rematch 时：

s:E -> old_peer 变为 s:E -> new_peer；

old link 上存在 ctrl_q，或者存在正在发送的 current；

old peer 当前或稍后恢复几何可用。

则 replacement s:E -> new_peer 已经能够开始 service，同时 retired old link 仍可继续 current，甚至从 ctrl_q 新启动一笔 transmission。

因此同一个 E direction 实际拥有两个并行 isl_rate_bps server。队列容量也事实上被拆成旧/new 两份。

这不是 fail-closed；它静默突破了 matching 所声明的单方向收发机资源约束。

要求修复后才能放行。

Reproduction condition

origin a 广播 snapshot，此时 E -> b_old；

远端 satellite 缓存该 snapshot；

topology rematch 为 a:E -> b_new；

fresh advertisement 尚未抵达，但旧 cache TTL 仍有效；

此时 b_old 的 E-link propagation/queue 数据会被当成 b_new 的数据使用。

这是普通 AoI stale 之外的实体身份错绑；当前没有 peer/topology-version mismatch 检查，因此不是 fail-closed。
