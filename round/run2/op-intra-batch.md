# 批内对账（op-intra-batch，2026-09-11）

> 依据：EFFECTIVE-RULES-R2 **§8.0**（R5 新增，因 run2 历史审查指认"批内五元组对账在流程中无属主"）。
> 执行者：主控。时机：初筛之后、历史审查之后（历史审查只审历史，批内归主控）。
> 基准：五元组（条件/困难/原因/机制/决策变化）+ 承重锚件同源性。

## 组 1：A3 ↔ B2（审查者指认：同锚同机制族）

| 维度 | A3 | B2 | 判定 |
|---|---|---|---|
| 承重锚 | S85KQ4FC 图2（21k pps / 17.5ms / 21% 丢包） | **同一锚、同一图** | **同源** |
| 机制族 | 双粒度决策：flow table 命中沿用 + θ_dec 超限触发 DNN 推理；决策缓存占用作前兆；超限降级规则路由 | 事件触发 + 流级动作复用 | **同族**（均为"降低推理调用频次"） |
| 条件 | 强度上升使到达率→推理饱和 | 热点迁移使推理负载集中 | **差异**（触发路径不同） |
| 困难 | 推理排队饱和致缓存溢出丢包 | 控制面与数据面共享资源被同时压垮 | **近同**（同一物理瓶颈） |
| 原因 | 塌陷源于决策器而非链路 | 推理丢包是独立于链路拥塞的到达率损失通道 | **近同** |
| 决策变化 | 决策结构（双粒度）+ 降级策略 | 决策执行机制（事件触发） | **实质重叠** |

**处置：合并**。理由：同一承重锚 + 同一机制族 + 同一物理瓶颈（推理资源），仅入口叙事不同（"强度上升" vs "热点迁移"）。B2 的淘汰线（决策时延占比 <5%）应并入 A3 的淘汰条件。

**合并后卡**：保留 **A3** 为承载 ID（`c37b7753f31`），吸收 B2 的贡献：
- 从 B2 吸收：**热点迁移场景下推理负载与数据负载同步集中**（这是 A3 未覆盖的触发路径）；
- 保留 B2 的淘汰线：决策时延占比 <5% → 整卡无空间；
- 登记：B2（`cc0e429067b`）→ `merged`，merged_into=A3。

## 组 2：B1 / C1 / C3（共享"Δq / EWMA 队列变化率入状态"特征原语）

| 维度 | B1 | C1 | C3 |
|---|---|---|---|
| 问题 | 热点位置不可辨识（拥塞场相位缺席） | 突发时长 vs 策略反应常数错配 | 突发下瞬时快照信息可辨识性 |
| 条件 | 空间非平稳 | 同均值不同 T_on/duty | 同均值不同突发 + 观测陈旧 |
| 原因 | 状态不含决定拥塞**位置**的变量 | 瞬态窗内策略仍在旧体制 + 降载后迟滞 | 快照无变化率与年龄语义 |
| 机制 | 注入**轨道相位** + 邻域队列**斜率** | Δq_τ + 突发龄计数 + 改路驻留 + 瞬态窗惩罚 | **信息年龄戳 + EWMA_τ(q) + 按龄加权 TD** |
| 决策变化 | 观测（相位） | 观测 + 动作约束 + 奖励 | 观测 + 更新权重 |

**判定**：
- **B1 与 C1/C3 不同题**：B1 的自变量是**空间位置可辨识性**，C1 是**时间尺度**，C3 是**信息年龄**。B1 用了"邻域队列斜率"这一共同原语，但那是**实现细节**，不是问题本身。
- **C1 与 C3 不同题但共享同一第一核验**：C1 要 ON-OFF 扫描测瞬态窗指标；C3 要 δ×hello 周期扫描测性能-陈旧度曲线。**两者都需"同均值突发扫描"基础设施**。

**处置：保留三张，但强制约束**：
1. **不得共用同一第一核验**：C2（同均值突发扫描协议）已经承担该基础设施角色 → C1/C3 **必须依赖 C2 的协议**，各自只做本卡特有的验证（C1 测瞬态窗指标、C3 测陈旧度曲线）；
2. 三张卡在深化时必须**写明与其余两张的差异**（尤其 C1/C3 共享"突发"入口）；
3. C3 另受历史审查判 ③（与 F1 家族卡真子集级重合），处置见组 4。

## 组 3：A1 ↔ C2（共享"语料审计 + 参数扫描协议"模板）

| 维度 | A1 | C2 |
|---|---|---|
| 自变量 | 负载**强度** | 负载**突发结构**（同均值） |
| 审计对象 | 训练-评估负载**强度**合同（11 篇） | 流量**过程模型**（20 篇） |
| 扫描协议 | 冻结策略 0.25–4× 强度扫描 + 重训差值 | CV × T_on × ρ 网格 |
| 改法 | 状态注入 λ̂/λ_ref | 域随机化 + (q, Δq, EWMA) 三通道 |
| 最强替代 | 普通混载训练 | 域随机化（**即 A1 的最强替代**） | 

**判定**：**自变量不同（强度 vs 突发结构），问题不同**——不是同题。
但审查者指出的"A1 的最强替代 = C2 的改法二"**属实**，说明两者在"训练分布覆盖"这一手段上**收敛**。

**处置：保留两张，但强制约束**：
1. 两卡若同时进入深化，**必须由不同深化者**处理，且各自在"简单替代猜想"节明确区分：A1 的替代针对强度维，C2 的替代针对突发维；
2. 若最终只保留一条主线，A1 与 C2 可**合并为"训练-评估负载合同"的统一议题**（强度维 + 过程维），但**不建议现在合并**——两者的第一核验是可以分开跑的（强度扫描 vs 突发网格），合并会掩盖各自的证据强度。

## 组 4：C3 的历史撞车处置（历史审查判 ③，主控裁决）

审查结论：C3 与 F1 家族卡（`cc24a3f94e5`）在**机制层**（年龄戳+EWMA+按龄加权 TD ⊂ F1 层②）与**核验层**（δ×负载扫描 ≈ F1 第一核验的参数化变体）双重重合；T-C1 的合法重开**已由 run1 的 F1 占据**。

**主控裁决**：**C3 不再作为独立卡推进** → 标记 `merged`（merged_into=F1 家族卡 `cc24a3f94e5`）。
理由：
- 同一问题第二次到达，且**机制是其真子集**；
- 其唯一可辩护增量 = "同均值突发 × 陈旧度交互轴"（＝ F1 继承自 T-C1 的 H2，至今待证）——该增量**本身就是 F1 的待验内容**，不是新题；
- 按 §8.0 判据表："五元组条件层几乎重合 + 同一承重锚"→ 合并。

**保留的资产**（写入 F1 卡）：C3 提供的**突发场景下的陈旧度参数化**（δ∈{0,0.5,1,2} × hello 周期），作为 F1 第一核验的一个附加维度。

## 组 5：A1 的历史撞车处置（历史审查判 ③，主控裁决）

审查结论：A1 与 run1-B3（`cc029fa6119`，状态 recommended_pending_review）**条件重合 + 原因假设逐字级近同 + 第一核验近重合 + 方法件/替代件互换**。

**主控裁决**：**A1 与 B3 对账合并**，以 B3 为承载 ID（`cc029fa6119`），吸收 A1 的独有贡献：
- 从 A1 吸收：**训练-评估负载合同审计表**（11 篇快查表，含"是否披露训练设置"字段）——这是 B3 没有的**元层面证据**，且直接支撑 B3 的"合同不披露"论断；
- 从 A1 吸收：**重训差值归因**（冻结策略跨强度 vs 每强度重训的差值）——比 B3 原有的"单负载×5点扫描"更能分离"覆盖不足"与"信息不可辨识"；
- B3 保留：规则基线对照（RL/ELB/SPF）+ 价值带定位 + 阈值显式化；
- 登记：A1（`c77e62eb00f`）→ `merged`，merged_into=B3。

**注意**：B3 当前状态为 `recommended_pending_review`，合并后需重新历史审查（其承重字段变化）。
