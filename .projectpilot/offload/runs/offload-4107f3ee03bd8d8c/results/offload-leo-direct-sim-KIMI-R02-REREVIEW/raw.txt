## 一、两个历史绕过的复现尝试

### 绕过 1：legacy receipt 免 external-witness 混为 v5 证据 —— **复现失败（已关闭）**

历史 blocker（`pre-fix-review-history.json` L56-L61）：默认分析器接受无外部见证的 v3/v4 receipt。当前代码的逐路径尝试：

- **默认模式直接塞 legacy receipt**：`v2_analysis.py:326-336`，receipt schema 为 v3/v4 且 `require_external_witness=True`（默认，`analyze(..., allow_legacy_internal=False)`，L461/L512）时在 L333-335 直接 raise `"external-witness mode requires current receipt evidence"`。测试 `test_v2_analysis.py:409-434` 精确复现此攻击（把 receipt 改写为 `LEGACY_RECEIPT_SCHEMA_V4` + governance V1，默认模式必须抛错）。
- **legacy artifact 自报 v5 schema**：则进入 L327-328 分支，`expected_governance_schema=V2`，L366-379 强制完整 governance witness 绑定 + `_verify_external_witness`（L133-167：nonce/run_id/authorization_sha256/receipt hash/五项 governance 字段逐一比对）。伪装者需同时伪造整条 V2 治理链与 VM witness，`--allow-legacy-internal` 对此分支**无任何豁免**（L366 的判断只看 governance schema，不看 flag）。
- **混编偷渡**：一个 v5 run + 一个 legacy run → L515-517 拒绝混合 evidence class；全 legacy 队列也只能在显式 opt-in 下得到 `evidence_class=legacy_v3_v4_internal_only`（L408-409）与 `claim_status=LEGACY_INTERNAL_ONLY`（L548-549）。
- **RUNBOOK 通道**：`RUNBOOK.md:29-34` 的分析命令不含 `--allow-legacy-internal`，默认 fail-closed。

结论：该绕过在当前 commit 不可复现，代码路径与测试双重闭环。

### 绕过 2：persisted claim_status 篡改 —— **复现失败（已关闭）**

历史 blocker：持久化校验不绑定 claim_status、不要求 claim-gate 状态一致。当前防线：
