# 精读笔记：ieee-11143359

**论文**：Beneath the Heavens: A Thorough Measurement Study of the Starlink Terrestrial Network
**出处**：IWQoS 2025, DOI: 10.1109/IWQOS65803.2025.11143359
**作者**：Yanbo Wu, Mingxin Cui, Gaopeng Gou 等（中科院信息工程研究所 / 国科大网络空间安全学院）

## 七要素（具体到数字机制）

1. **研究对象 / 问题**：Starlink 地面网（SLTN：用户终端 UT、地面站 GS、PoP）的架构、资产、拓扑与路由策略。现有研究集中于空间段，地面段是黑盒；理解不足已导致安全评估误扫无关主机。
2. **方法 / 系统**：主动+被动测量框架三件套：
   - **StarCollect**：以 OSINT 真实用户公网 IP 为种子，经 Origin AS 映射 + Passive DNS 迭代收敛（域名规律：95% 输入 IP 关联 `customer.*.{pop, mc}.starlinkisp.net` 子域），建标准化网络资产库 NADB。
   - **StarTrace**：TTL-limited traceroute 改进——用 ICMP ECHO/DNS/HTTP GET 补充响应绕防火墙；重复 traceroute ≥15 次后 >80% 结果一致，取众数路径与平均时延。7 台五大洲云服务器 + 70 个 RIPE 探针（20+ 国家）+ 招募志愿者；定义 5 类路径（Path-1/2 接入、Path-3 同 GS、Path-4 同 PoP 异 GS、Path-5 跨 PoP），共发送 >50K 探测包。
   - **StarScan**：ICMP+TCP SYN 扫前 1024 端口，Nmap 16 种探针取 banner，辅以 Shodan（1500+ 端口）。
   - **OSINT**（首次用于 SLTN）：以默认网关 192.168.100.1 / 100.64.0.1 为关键词在社区搜 traceroute，手工收集 87 份 traceroute + 120 位用户公网 IP/地理位置（20+ 国家、六大洲）；仅用 2024 年后数据（2022 年底 Starlink 做过架构标准化调整）。GS/PoP 位置：137 GS、27 PoP（16 国）。
3. **关键数字 / 发现**：
   - NADB 元数据：2023-05 → 15,804 /28 前缀、266 域名、107 国；2024-05 → 20,828、278、130；2025-01 → **23,562 /28 前缀（48% 增长）、290 域名、6 个 AS、143 国家**。较 2023-01：IP +48%、覆盖国 +52%、服务区 +182%。
   - 关键 AS：SpaceX AS14593 为核心（329,984 IP、131 国、对等 370+ AS，29 上游仅 4 下游）；另有 AS45700、AS27277、Google AS36492、AS14597。
   - 拓扑：用户→互联网对称 4 跳：Hop0 用户节点(192.168.100.1) → Hop1 网关节点(100.64.0.0/10) → Hop2 链路节点(172.16.0.0/16) → Hop3 PoP 出口节点(206.224.64.0/19, 149.19.108.0/23, AS14593)。Hop0→Hop1 占内网时延 >67%（卫星无线段）。
   - **PoP 切换影响时延**：蒙古用户 2024-10 前连德国 PoP，之后切日本；柏林云服务器实测均值 160.63 ms → 411.93 ms。
   - 资产分类算法（Algorithm 1，基于 RFC 8805 用户段 + Passive DNS 域名 + traceroute 验证）：**79.6% IP 属用户节点，2.3% 属 PoP 出口节点**，余为未知/弃用。
   - 扫描：2025-01 活跃主机开放端口 >64.9K（2023 初仅 3.7K）；用户节点端口服务 TOP：HTTP 24.5%、无线路由器服务 7.3%、SSH 6.5%；出口节点仅 9 个开放端口（BGP）。
   - 内部路由策略：同 GS 用户通信在网关节点即完成；跨 GS 经链路/出口节点中转；跨 PoP 经全球 PoP 出口节点逻辑互联的**内部骨干网**（MPLS，经 ICMP trace 识别）直连，不经互联网中转。
   - **路由策略变化影响时延**：柏林→西雅图，2024 年 4-5 月经 Starlink 骨干（法兰克福→芝加哥 PoP），优化路径均值 135.20 ms = 传统路径（170.21 ms，直连西雅图 PoP）的 **79.43%**；2024-06 后回退传统策略。柏林→悉尼也有类似优化。
   - 96% 用户 IP 地理位置对应邻近 PoP 而非真实位置（IP 定位只有 PoP 级精度）。
4. **实验 / 数据规模**：测量跨度 2023-01 至 2025-01；50K+ 探测包；87 份社区 traceroute；120 用户 IP；137 GS / 27 PoP；NADB 三时点快照。
5. **局限**：黑盒系统、网络波动；志愿者/OSINT 依赖手工收集；路由策略变化的频率与触发机制"未报告"（作者自列 future work）；每个 PoP 覆盖国家未测；骨干拓扑恢复仍部分依赖用户志愿者。
6. **可复用性**：NADB 标准化资产库 + 分类算法开源思路；Path-1 + Hop3 IP 地理定位可让用户自判所连 PoP（作者在开发用户工具）；外部互联网探针亦可恢复骨干拓扑（BGP 策略使部分回程路径穿骨干）。
7. **对 QoS 评估的核心警示**：PoP 周期性切换 + 骨干路由策略周期性变化都会引起显著时延波动；做 QoS 评估必须同时记录路由路径，否则天气/卫星运动等因子的影响评估被污染。（另：Starlink 内部每 15 秒调整一次 [14]）

## 与选题空间的关系

- **直接支撑"地面段不可忽略"论点**：本文证明 PoP 切换（160→412 ms）与骨干路由策略切换（135 vs 170 ms，差 ~21%）是 QoS 的一阶因子，为我们做 LEO 直连仿真时建模地面段路由/换 PoP 事件提供了实测依据与机制（4 跳拓扑、各跳 IP 段 100.64.0.0/10、172.16.0.0/16、206.224.64.0/19、149.19.108.0/23 可直接用作仿真参数）。
- **选空间隙（作者自列 future work）**：路由策略变化的触发条件与频率未研究、PoP 覆盖国家未测——可做事件驱动的路由/拓扑动态仿真或预测。
- **与 RL/自适应调度选题的关系**：本文非 RL，但其"路径不稳定 + 周期性切换 + 时延跳变"的实测分布正是 RL 链路/路由选择、自适应码率或切换决策类工作的真实环境依据；NADB + 分类算法可作为仿真校准数据源与 trace 采集方法学参考。
- **方法学可迁移**：StarTrace 的"重复 ≥15 次取众数路径"与 OSINT 众包式采集，可作为我们实验平台采集真实 SLTN trace 的低成本方案，替代大规模招募志愿者。
