# 论文选题去锚定与材料清理设计

## 目标

阻止后续 Agent 把既有候选题、既有实验解释或平台现成功能当成已经确定的论文方向，同时保留可追溯的论文原文笔记、来源登记、实验原始证据和仓库治理链。

本设计从已冻结并推送的 `987195135ce099fb4c56304b9e42056e3bb2a24a` 建立续作分支。旧分支不再写入；本分支是该清理任务的唯一写入者。

## 已确认的问题

1. `AGENTS.md` 只规定证据、Git 和实验门禁，不规定论文题目，不是需要清理的对象。
2. `AGENT-START-HERE.md` 的统一阅读顺序会让选题 Agent 在独立形成问题之前接触当前实验状态和旧实验计划。
3. 三份 CURRENT 文档仍把远端信息价值、状态陈旧、图模型收益来源和联合路由调度作为默认候选，构成重复锚定。
4. 原始调研任务要求最终推荐一个中心问题，容易把“完成交付”误当成“证据足以冻结”。
5. `LITERATURE/KNOWLEDGE-MAP.md` 和 `LITERATURE/notes/*.md` 在文档治理中是 `SUPPORTING`、不得指导当前工作，但其中又出现“定稿”“建议冻结”和“只差用户拍板”，权威角色冲突。
6. 把旧实验连同旧解释在选题初期全部交给 Agent，会把已有异常、内部术语和平台能力变成候选题生成器。旧实验应在候选形成后用于攻击、边界核对和可行性判断。

## 采用方案

采用“删除误导性成品 + 保留底层证据 + 重构官方入口 + 分阶段揭示实验”的组合方案。

不采用仅加警告的方案，因为旧入口和重复的冻结措辞仍会持续引导 Agent；不采用删除全部文献和实验材料的方案，因为那会破坏研究谱系、反例复用和证据追溯。

## 精确删除范围

删除以下已跟踪文件；其内容仍由 Git 历史保存：

- `LITERATURE/notes/ONE-PAGE-OPENING-v0.1.md`
- `LITERATURE/notes/ONE-PAGE-OPENING-v1.0.md`

重写 `LITERATURE/KNOWLEDGE-MAP.md`，只保留：

- Claim Map；
- Assumption Map；
- Evidence Map；
- 空白点检索与其证据等级；
- 逐篇深读事实和未核实项。

从当前版本删除下列决策性内容：

- Puzzle 和候选 RQ 生成；
- 9 关初筛与定稿；
- F1/F2/F3 排序和推荐；
- “拟冻结”“建议冻结”“只差用户拍板”等状态；
- 竞争假设、扰动合同、年龄扫描和 T1 实验设计。

这些内容不是被宣布为错误，而是从“当前知识地图”中移除，避免 supporting 文档兼任选题裁决者。需要追溯时使用 Git 历史。

## 证据防火墙

选题任务按四阶段读取材料：

1. **冷启动问题生成**：只读取领域边界、研究对象和不可违反的科研规范；不得读取旧中心问题、旧候选排序、旧实验解释和平台功能清单。产出 3 至 5 个可观察现象、未知原因及立即淘汰条件，不排序。
2. **外部文献碰撞**：先用论文原文和正式来源核对候选是否已经被回答；仍不得用本项目实验为候选加分。
3. **本地证据揭示**：候选已经形成后，才读取旧实验。实验只用于反证、边界、测量可行性和成本判断。必须把原始观测与历史解释分开，并回答“如果平台没有这个现成功能，问题本身是否仍值得研究”。
4. **廉价 Pilot 与裁决**：只有直接近邻、关键变量可测、至少一个竞争解释可区分、最小 pilot 可行且成功判据不预设结果时，才允许推荐冻结。证据不足时明确保留候选，不强制选一个。

## 文档修改范围

- `AGENT-START-HERE.md`：为论文选题增加独立路由，使冷启动阶段先读 `LITERATURE/README.md`，延后实验计划和历史结果。
- `LITERATURE/README.md`：成为短小的选题与文献治理合同，承载证据防火墙、实验揭示规则和冻结门。
- `ANALYSIS/CURRENT-EXPERIMENT-READINESS.md`：当前状态改为“中心问题未冻结；旧候选和旧实验不得生成选题”。
- `ANALYSIS/EXPERIMENT-PROGRAM.md`：只保留“实验暂停，等待问题形成”的门禁，撤销旧四候选默认地位。
- `ANALYSIS/PLATFORM-CAPABILITY-LEDGER.md`：声明平台能力只能在候选形成后判断可攻击性，不能决定重要性或新颖性。
- `LITERATURE/notes/README.md`：第一遍阅读只记录论文自己的 Question/Claim/Mechanism/Evidence/Assumption/Boundary/Tension；“与我们实验的关系”只能在第二遍对账时添加。
- `LITERATURE/notes/00-READING-QUEUE.md`：标为旧问题驱动的种子语料，不是系统综述总体；删除“中心问题拟冻结”和“空白点关闭”等裁决性变更记录。
- `ANALYSIS/DOCUMENT-STATUS.json`：更新复核日期和用途，保持知识地图与笔记为 `SUPPORTING / may_direct_current_work=false`。

不修改 `AGENTS.md`、实验原始工件、逐篇 raw 笔记、`SOURCES.csv`、本地忽略的组会历史材料或 memory。它们仍可用于追溯，但不得进入选题冷启动阶段。

## 验收标准

1. 两份 `ONE-PAGE-OPENING` 文件在续作分支中不存在。
2. 当前知识地图不含 `拟冻结`、`建议冻结`、`F3×F2`、`推荐与裁决`、`扰动合同`、`T1 判别实验`。
3. 官方入口明确区分选题任务和实验/实现任务，并规定旧实验延后揭示。
4. 三份 CURRENT 文档不再把旧四候选作为当前搜索边界。
5. 阅读规则不再要求每篇论文第一遍就映射到本项目实验。
6. 文档治理检查为零错误、零警告；工作区检查不报告未声明的脏文件。
7. `git diff --check` 通过，diff 只包含本设计声明的文档清理。

## 明确不做

- 不启动任何实验、训练或网络文献检索。
- 不决定新的中心问题。
- 不把韧性、信息年龄、GNN 或联合调度中的任何一个改成新的默认方向。
- 不删除论文原文笔记、来源登记、实验原始证据或历史 Git 提交。
- 不修改旧生产者分支。
