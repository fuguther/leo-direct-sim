3.2 对 F2 的反例攻击

替代解释：测试里的 "00"*16 只是随手构造的 dummy key，真实历史 v1 checkpoint 不会有错误宽度。

这个解释完全可能；我没有历史 artifact，因此不能声称生产环境已有 16-byte legacy 表。

但它仍不能消除代码问题。当前测试的标题和断言不是“parser accepts arbitrary fixture”，而是明确把它定义成“legacy v1 table migrates”；loader 本身也没有任何约束去区分“真正旧表”和“状态表示已经过时/损坏的表”。更关键的是该失败模式不是安全地拒绝，而是加载后在 eval 中静默进入 deterministic zero-row fallback。因此即使所有现存历史 artifact 恰好都是正确宽度，当前 gate 仍未证明“迁移 artifact 与当前 contract observation representation 可兼容”。

这正是迁移代码应做的基本 invariant：

∣key∣=CONTRACT_DIMS[contract]×8

至少 v1 若声明 key 为当前 V2 float64 observation bytes，就应执行该检查；如果历史 v1 确实有另一种 state width，则不能“直接加载”，而应使用显式版本化转换。

因此 F2 保持 major。

**FACT：**当前 fixture 16 bytes；C3 runtime key 112 bytes；loader 放行；eval miss 返回 zero row。
**INFERENCE：**真实历史 artifact 中存在相同不兼容情况。
**未验证：**所有曾发布 legacy-v1 q_table 的真实 key width 分布。

3.3 对 F3 的反例攻击

普通“坏 JSON”最常见的是 {bad json 一类语法错误，该情况已经被 JSONDecodeError 捕获。非法 UTF-8 更接近文件损坏/二进制污染边界，而不是普通配置错误，因此它不影响核心 checkpoint contract 安全性。

所以 F3 保持 minor，不用于单独阻断 PR；它只说明此前“所有损坏 JSON 均转成 LearningUnavailable”这一绝对表述不能成立。

阶段 4：修订

初始检查 _verify_checkpoint_metadata 时，我的临时判断偏向“整改已经闭合”：六字段确实没有漏项，missing/symlink/普通 JSON 损坏也都被 fail-closed。

对抗后，这个判断需要修订。

最终应拆成三层：

字段一致性层：通过。 六个要求字段确实全部校验。

receipt contract 一致性层：通过。 DDQN/Q-learning 都新增了 learning.contract == routing.contract。

checkpoint 原始 contract provenance 层：未通过。 sibling metadata 没有独立 identity anchor，因此在任务明确要求的 forged-metadata 威胁模型下，可以把同一 checkpoint 重标为等宽的另一 contract。

legacy migration representation 层：未通过。 loader 不检查 key representation 宽度，并且现有测试已经证明错误宽度表会被“成功迁移”。

因此最终判定为：

REQUEST_CHANGES

这不是因为 DDQN 六字段整改做错了；相反，那部分实现是正确的。阻止批准的是两个更深层问题：F1 使 metadata 只是自洽声明而非独立 contract 证据；F2 允许“成功加载但永远不命中”的 legacy Q-table 假绿。

建议最小整改方向：

F1：不要再把未锚定 sibling metadata 当作“独立 provenance”。较稳妥方案是做显式 migration：读取旧 artifact + 受信任 provenance，生成一个contract 内嵌到 payload/新 checkpoint identity 中的新 artifact，然后让 resolved config pin 新 artifact SHA。若必须保留 sibling metadata，则 resolved config/授权 manifest 必须同时 pin metadata SHA。

**F2：legacy Q-table 加 state-key invariant。**解析 hex 后要求 len(key_bytes) == CONTRACT_DIMS[self.contract] * 8；若历史版本 state representation 不同，则应该升级 schema 并明确转换，不能直接装进当前 self.table。

同时验证 payload.schema，并区分 "contract" not in payload 与 "contract": null；只有真正字段缺失的已知 legacy schema 才进入迁移。

**F3：**把 UnicodeError/UnicodeDecodeError 纳入统一 LearningUnavailable 包装。

增加真正的 adversarial 回归：C3 DDQN bytes + C4 forged metadata 必须拒绝；错误 key-width legacy 表必须拒绝；invalid UTF-8 metadata 必须得到 LearningUnavailable。

open_items
