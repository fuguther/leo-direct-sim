## 结论（E1）

1. **扩大局部观测范围（obs_hops 1→3）不改变路由性能**：三个档位下完成率在小数点后
   四位一致，配对差中位数为 0，CI 不含 0 也不含非零 → 无证据支持"多跳观测有价值"。
2. GAT 学习臂在低/中档（50/100）≈ hop 基线（≈0.997），高档（200）略低于 hop
   （0.9356 vs 0.9475）——方向上是"学习失败"，但幅度小。

## 可能的结构性原因（待 E2 + fate 拆分证实，先记候选）

- uniform 流量下最短路径近乎最优，学习/观测没有发挥空间；
- 部分损失发生在接入侧（非 ISL 路由），路由策略的改进空间被压缩。

## fate 拆分证实（关键）

200 Mbps 档（唯一有明显损失的档）fate 分布（30 个 eval run 聚合）：

| 类别 | 数量 | 占比 |
|---|---:|---:|
| delivered | 41952 | 93.5% |
| **access_loss**（接入拒绝/队列溢出） | **2568** | **5.7%** |
| **isl_loss**（星间链路丢失） | **0** | **0.0%** |
| no_route / deadline | 0 | 0.0% |
| in_system（期末在途） | 330 | 0.7% |

→ 高载下唯一损失源是**接入侧（5.7%）**，ISL 路由损失为 0。这从机制上解释了负结果：
路由平面没有可改进的空间（无 ISL 拥塞/丢包），观测范围、聚合方式都无法改变接入侧瓶颈。
（50/100 档 access_loss 也为 0，loss 仅为期末在途 0.3%。）
