github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/kernel.py#L600-L621

后果

这不是单纯“攻击者既然能改硬盘就什么都能改”的泛化威胁。checkpoint SHA 已经被设计成不能随便改，问题恰恰在于：只改未被锚定的 sidecar，就能绕过专门新增的 contract binding，而无需改被 resolved config 钉住的 checkpoint。

尤其 legacy migration 中，旧表本身没有 contract 字段，因此 metadata 是恢复 semantic provenance 的唯一依据。如果 metadata 不被独立绑定，“迁移合同”实质上还是调用时指定，而不是训练时不可变事实。

影响包括：

C3 模型/表被当成 C4 使用；

相同维度但不同 observation semantics 的实验发生静默污染；

eval 结果看起来 checkpoint SHA、contract、receipt 全一致，却不是所声明 contract 下训练出来的策略；

研究结果的学习臂身份不可追溯。

更严重的是，Kernel 在运行结束时会调用 learner 的 save_and_verify：

github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/kernel.py#L1770-L1786

而 TabularQ save_and_verify 会把当前 self.contract 重新写进新 q_table.json：

github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/learning.py#L770-L797

所以一旦旧 checkpoint 被错误重标加载，后续还可能生成一套完全自洽的新格式 artifact，把错误 provenance“洗”成当前 contract。此后 receipt 的 learning.contract == routing.contract 也只能看到被洗后的当前身份。

严重度：blocking。 PR #42 的目标正是 checkpoint contract binding；这个缺口直接让目标可绕过。

证据

DDQN metadata 读取：

github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/learning.py#L373-L384

meta_path.read_text(encoding="utf-8")

再 json.loads(...)

只捕获 (OSError, json.JSONDecodeError)

TabularQ legacy metadata 同样如此：

github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/learning.py#L673-L688

推理链

如果 metadata.json 是合法 UTF-8、但 JSON 语法损坏，例如截断对象，那么 json.loads 会产生 JSONDecodeError，当前代码正确转为 LearningUnavailable。

但如果 metadata 文件本身含非法 UTF-8，例如开头字节等价于一个无效 UTF-8 序列，异常发生在 Path.read_text(encoding="utf-8") 解码阶段，是 UnicodeDecodeError。该异常不属于当前捕获的 OSError 或 json.JSONDecodeError，因此不会进入统一的：

raise LearningUnavailable("... metadata unreadable ...")

而会以原生异常越过 learner 的受控失败边界。

复现条件

TabularQ 不需要 TensorFlow，理论本地最小复现是：

准备一个 SHA 与 resolved config 匹配的 legacy q_table.json；

sibling metadata.json 写入非法 UTF-8 bytes；

构造 TabularQLearning；

当前静态代码推导的结果是 UnicodeDecodeError，而不是 LearningUnavailable。

DDQN 同理，但 constructor 首先要求 TensorFlow，因此完整动态复现需要 TF host。

影响

这不会把错误 checkpoint“误接受”，所以不是 fail-open；但它违反这次明确验收要求中的“损坏 JSON 全部 fail-closed 为受控 LearningUnavailable”。调用层如果只按学习不可用错误做统一降级、记录或 CLI 错误处理，就会出现异常类型泄漏，重新产生此前 H2-2/H2-6 一类“底层畸形输入绕过受控错误边界”的工程问题。

严重度：major。 原因不是安全范围大，而是它直接不满足本轮列明的终审验收项。

建议将 decode 错误纳入受控异常，例如显式包含 UnicodeError，并增加非法字节回归测试。

github://fuguther/leo-direct-sim/blob/c1aefab5827250a6157b83be45fb13f9c75d0dbf/CODE/leo_sim/learning.py#L770-L781

3.3 对 F3 的反例

“checkpoint SHA 已经固定完整文件，schema 不需要另验。”

这个解释部分成立，所以我把它降为 minor。

SHA 解决的是“这是预期字节文件吗”，schema 解决的是“reader 是否明确承诺理解该格式”。如果 config 本来就特意批准这一具体文件，schema 缺失检查短期未必造成错结果；但一旦迁移、手工 checkpoint 或版本迭代发生，这种 permissive reader 会扩大兼容面。因此它仍是 fail-closed 完整性问题，但不足以阻止本 PR 单独合并，若没有 F1/F2 我不会仅因它 REQUEST_CHANGES。

Kernel 没有单独传 metadata digest 给 learner。

Receipt 已对 DDQN/Qlearning 校验 learning.contract == resolved routing.contract。

q_table.json writer 写 schema，reader 没有对应 schema equality check。

本 commit 中专家审阅文档只有 §A-H。

INFERENCE

在没有额外外部 metadata anchor 时，同一个 legacy table 可通过重写 metadata 改变其被接受的 contract。

同条件下 C3 DDQN 可被 metadata 重标为 C4，并越过 shape guard。

被错误重标的 checkpoint 经过 save_and_verify 后可能形成新的、内部完全一致的当前-contract artifact。

非法 UTF-8 metadata 实际构造时会以原生 decode error 穿出，而不是 LearningUnavailable。

这些 inference 都有直接代码路径支撑，但本 Worker 按合同没有执行动态复现。

未验证

合同外 governance/authorization 是否另有“metadata 文件 SHA / checkpoint 目录 Merkle/hash / manifest artifact hash”并在 learner 初始化之前强制验证。

TensorFlow 主机上 C3→C4 DDQN metadata 重标的完整动态复现。

当前 commit 全测试套运行结果。

keras.models.load_model 遇到损坏但 SHA 被合法配置绑定的模型时，异常是否也应统一包装成 LearningUnavailable；当前代码未包装，但具体异常族未在本 Worker 运行。

checkpoint 文件本体是 symlink 时的政策是否要求与 metadata 一样拒绝；当前 loader 对 checkpoint 只用 is_file()，没有 is_symlink()。

4.2 合并前必须修的最小集合
必修 1：给 metadata 本身建立独立信任锚

至少选一种真正形成不可循环证明的方案：

resolved/authorized config 额外绑定 checkpoint_metadata_sha256，加载前对 sibling metadata 实际 bytes 求 SHA 并比较；

或使用一个外部授权 manifest，同时绑定 checkpoint SHA、metadata SHA、contract、algorithm；

必修 2：统一 metadata decode failure 为 LearningUnavailable
