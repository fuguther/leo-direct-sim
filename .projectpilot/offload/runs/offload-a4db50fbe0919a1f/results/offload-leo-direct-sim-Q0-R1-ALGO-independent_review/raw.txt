Q0 完全信息下最优上界算法选型：独立复核结论
0. 结论先行

核心结论：严格按当前任务定义的 Q0——“能瞬时读取全部当前全局状态，但看不到未来”——不存在一个 time-expanded MILP / min-cost-flow 能直接被称为 Q0 的普适精确最优算法。

应区分三个问题：

Q0-I：当前全局状态完全可见，仍保持现有逐包逐跳动作和现有 DRR/priority/物理执行语义。
若未来到达、GE、拓扑演化等的转移概率模型已知，理论上的精确算法族应是 事件驱动 SMDP / PDMP 动态规划（Dynamic Programming）。本平台有确定性服务轨迹和随机/确定性中断事件，PDMP/SMDP 比固定时间步 MDP 更自然。Almudevar 给出了受控 piecewise-deterministic Markov process 转成离散决策过程并做 DP 的形式。
工业与应用数学学会

Q0-F：连未来到达、未来几何/中断轨迹也已知，即 clairvoyant offline oracle。
这时最合适的是 continuous/event-time MILP 或 CP-SAT；time-expanded MILP 是次选。Boland 等的 continuous-time service network design / dynamic discretization discovery 说明，可通过部分时间展开保持连续时间精确性，而无需预先把全部时间点离散化。

+1

但它不是任务定义的 Q0。

实际大规模在线 Q0：数十星、千包级。
精确 DP 和包级 MILP 都会组合爆炸；工程上只能用 rolling-horizon MILP/MPC、MaxWeight/backpressure、启发式或 RL 等近似策略。Rolling horizon 本身有最优性损失，文献给的是误差界而非一般全局最优保证。

2. 平台为什么不是普通网络流问题

当前 kernel 的关键物理语义包括：

包有独立 bits/deadline/path；

GSL/ISL 服务是有限资源；

ISL 数据和控制共享队列，控制是 non-preemptive priority；

服务与 geometry loss、GE outage、deadline、hard-retirement 竞速；

链路服务开始后不能暂停再恢复；

propagation 也是实际时间；

GSL 有 acquisition、K-slot、BBM/MBB/DRR；

当前 action 仍是逐包的 {deliver,N,S,E,W}。

去掉远端 topology

同样通常破坏 Markov sufficiency。

去掉 AoI

要区分两种情况。

真正 Q0 instantaneous truth

若字段本身是直接读取当前全局真值，则信息年龄为 0：

C1–C7 cache observation

11. 信息裁剪后的算法选择逻辑

可以直接冻结成实验判定规则：

观测仍 Markov sufficient
→ 原 SMDP/DP 仍理论适用。

非 Markov，但 hidden-state transition/observation model 已知，规模极小
→ belief-state POMDP DP。

非 Markov，规模大，但 centralized history 可用
→ recurrent RL / approximate belief policy。

每星只能拿自身 + 邻居状态
→ decentralized RL / MARL；若目标偏长期 throughput，可加入 backpressure baseline。

只用 instant local metric
→ greedy / shortest-path / queue heuristic，仅作低成本 baseline。

不能因为“删了一些信息”就继续把 full-state optimizer 喂一个残缺向量，并仍称其最优。

14. 独立复核发现

F1 — blocking — Q0 与 clairvoyant upper bound 目前存在概念混淆风险。
严格 current-state-only Q0 的 exact family 是 stochastic event DP（有已知 transition law 时）；未来轨迹 MILP 必须标 Q0-F。仓库本身已经要求 Q0-I/J/F 分离。

F2 — major — plain time-expanded/min-cost flow 不是本平台 packet-level exact optimizer。
核心缺口是 packet indivisibility、non-preemptive resource conflict、deadline、buffer 与 interruption，而不是单纯 dynamic graph。

F3 — blocking — M1 shaped return 不得成为 Q0 最优性指标。
正 forward reward 会造成 route-length incentive；仓库已记录为 blocking reward flaw。应固定 physical objective。

F4 — major — 允许 WAIT/joint scheduling 会改变 action/control class。
它应命名 Q0-J，不能拿其增益归因为信息可见性。

F5 — major — 数十星/千包 full exact 没有现实复杂度预算。
精确 solver 应限 tiny canonical instances；full scale 改 rolling horizon/online control。

F6 — major — 信息裁剪后若 observation 不再 Markov，不能继续宣称 full-state DP optimal。
应转 POMDP/approximate belief/recurrent/decentralized policy；local greedy 只能作 baseline。

Open items

Q0 是否知道未来 stochastic transition law？ 当前只明确“看不到未来 realization”。若 transition law 也未知，则 expected-optimal SMDP 的定义不完整。

预测 deterministic orbital ephemeris 是否算“看未来”？ 当前平台说明强调 kernel 只读当前几何；若 planner 可由 orbital model 推出未来 topology，则实际上获得了确定性 future information。

主 Q0 是否严格冻结 Q0-I 的 DRR / control priority / forced-deliver / 无 WAIT？ 建议答案为是；否则必须另列 Q0-J。

deadline 等时刻语义尚未完全冻结。 仓库 D6 仍记录 >= / > 以及 service_end==deadline 差异；exact oracle 与 kernel 比较前必须统一。
github://fuguther/leo-direct-sim/blob/1599d3e3c7d5d74f22ddb497969f28fe8b90b73c/ANALYSIS/EXPERT-REVIEW-20260816.md#L43-L52

若保留 control-plane traffic 做公平信息归因，需要明确 tiny optimizer 如何处理未来 control generation：未知未来 arrivals，还是固定为 kernel 外生 schedule。
