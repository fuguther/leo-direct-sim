F1 — BLOCKING — queued learning-forward packet 在 rematch 后会触发 KernelError

FACT

动态重匹配只把旧链路 data_q 中的数据包取出并 _hold_packet() 回 satellite holding；它没有处理包上尚未闭合的 learning transition：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L955-L980

Forward action 的 queue reward 明确要到 真实 ISL service start 才写入 pkt.learning_reward：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L1490-L1510

因此，包如果尚在 data_q 就遇到 rematch，其状态为：

learning_state != None

learning_action == "forward"

learning_reward == None

下一次 pending 重决策调用 _learning_action() 时，这种状态被代码明确判为非法，并抛 KernelError("unsettled non-deliver learning transition at re-decision")：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L2059-L2088

KernelError 是普通 RuntimeError；run() 的受控中断只捕获 CapExceeded 和 FateError，该错误不是正常 fate：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L56-L63

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L2280-L2297

Reproduction condition

开启 DDQN/Q-learning；制造一个已经选择 forward、但仍排在即将被替换的 ISL data_q 中尚未开始 transmission 的包，例如降低 ISL rate/制造前序 backlog；在 service start 前触发拓扑重匹配改变该 direction 的 peer；下一次 _pending_ticker() 重决策即可进入上述异常路径。

这是确定性的执行错误，blocking。

F2 — BLOCKING — retired-link control drain 会把旧拓扑的 directional metrics 静默解释成新拓扑链路

FACT + INFERENCE

设计明确规定：

queued data 回退到 pending；

queued control 留在旧 ISL drain；

拓扑、reverse adjacency、control tree 立即换成新拓扑。

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L61-L77

实现与这一点一致：_recompute_topology() 只清空 data_q，没有清 ctrl_q，旧 link 被放入 _retired_isls：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L955-L980

而 ISLLink worker 没有 retired-state 禁止启动；只按 geometry/GE/TTL 决定是否继续发送，因此 queued control 确实会在旧链路上继续 drain：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L560-L670

控制快照在生成时把当时 ISL 的 queue/propagation 按 direction 构造；收到后，只要 TTL 有效就无 topology-version/peer 检查地写入 cache，并且旧包继续依据当前 control_children 转发：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L1740-L1830

ControlPacket 本身也没有 topology epoch 或 peer-binding 字段：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L211-L225

与此同时，delay/capacity routing 使用当前 topo把 (a,b) 重新转换为 direction，然后按该 direction 读取 cache 中的 isl_propagation_s / isl_queue_bits：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/routing.py#L195-L244

INFERENCE

因此如果：

旧 topo: satellite A, E -> X
新 topo: satellite A, E -> Y

而一个 rematch 前生成的 snapshot 在 rematch 后才到达，cache 中 "E" 的 propagation/queue 是 A→X 的历史状态；routing 却会把它作为当前 A→Y 的 metric 使用。

这不是正常的 AoI/staleness：信息甚至不再描述同一条 edge。

Reproduction condition

启用 control plane + delay 或 capacity routing；让控制包 TTL 跨越 rematch；在某 origin 的 direction peer 从 X 改为 Y 时，使旧 snapshot 处于 retired ctrl_q、service 或 propagation；rematch 后让它成功到达并参与下一次 route calculation。

若 advertise_interval_s == recompute_interval_s，风险更高，因为 control advertiser 的 process 在 topology ticker 之前创建：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L880-L900

结论：控制包 drain 在 ledger conservation 上是显式的，但 topology semantics 不是 fail-closed。 对 delay/capacity 科学结果属于 blocking。

F3 — MAJOR — 动态 rematch 绕过 max_entities，retired ISL 可持续累积

FACT

max_entities 只在 Kernel 初始化时对初始 ISL 数量检查：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L827-L840

每次拓扑变化则：

将旧 link 永久追加到 _retired_isls；

为新 peer 创建新的 ISLLink；

没有重新执行 max_entities 检查。

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L955-L976

_all_isls() 明确同时保存 current + retired：

github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L941-L945

Reproduction condition

令 max_entities 仅略高于 initial entity count，配置短 recompute_interval_s，脚本 geometry 每个 epoch 至少改变一个方向。第一次/若干次 rematch 后实体数即可超过配置上限而不会 CapExceeded。

这是 bounded-kernel 的 fail-closed 失效，severity major。

retired-link 语义的明确判定

不是“queued control/data 都 drain”。

准确行为是：

queued data：不 drain。 从 retired link data_q FIFO popleft，移除旧 ISL queue-area，再按顺序 append 到 satellite holding；holding 满则显式 HOLDING_QUEUE_OVERFLOW。

queued control：drain。 留在 retired link 的 ctrl_q，允许继续在旧 peer 上启动 transmission，直到发送、TTL expiry、链路失败或 horizon。

已经成为 link.current 的 data/control：继续旧链路 service，不被 rematch 中断。

已经 transmission 完成、处于 propagation 的 data/control：继续到原 peer。

最终 accounting 使用 current+retired links，因此 bits/queue-area/control ledger 本身基本守恒。

因此：data migration 的守恒处理是 fail-closed；control drain 的账目也是显式的，但其拓扑信息语义不是 fail-closed，F2 必须修。
