Findings
F1 — major — 动态拓扑在 t=0 提前生效，且短于 interval 的运行会产生错误的 receipt effective 标记

FACT

设计规定 topology ticker 先 timeout(interval)，仅在之后且 now < horizon 时执行重算。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L58-L63

但 Kernel 只要 recompute_interval_s != None，构造初始拓扑时就立即调用动态 neighbors_at(..., t=0.0)，而不是静态 neighbors。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L798-L801

真正的 ticker 仍然等一个完整 interval 后才增加 topo_recomputes。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L948-L980

Receipt 则仅以 topo_recomputes > 0 判定 dynamic_topology 是否 effective。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/receipt.py#L144-L154

INFERENCE / reproduction condition

令 0 < horizon < recompute_interval_s，并令 neighbors_at(...,0) 与静态 neighbors(...) 不同。整个运行实际上已经使用动态匹配拓扑，但 ticker 一次都不会执行，最终 topo_recomputes == 0、effective.dynamic_topology == false。

这同时破坏了“重匹配间隔何时开始生效”和机制回执的真实性。

F2 — blocking — 退役旧 ISL 与新 ISL 可同时占用同一 E/W 方向收发机，瞬间突破物理链路容量

FACT

D2 匹配合同明确以每颗卫星的 E/W 方向槽作为独占收发机资源。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L40-L48

每个 ISLLink 都拥有独立 queue/current/wake，并启动独立 _run() SimPy process，没有可见的 satellite-direction 共用 service arbiter。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L559-L589

重匹配时，旧对象被放入 _retired_isls 继续存在，同时同一 direction 可立即创建一个新的 ISLLink。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L956-L980

此后正常决策直接对新的 self.isls[sat][direction] 入队并启动服务。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L2185-L2210

设计还明确要求旧链路控制队列继续 drain。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L64-L74

INFERENCE / reproduction condition

在 rematch 时令旧 s:E->old_peer 有长时间在服包或待 drain 控制包，并让新 s:E->new_peer 随后收到数据/控制包。旧、新两个独立 _run() 均可调用 _transmit()，代码中没有对 (sat, direction) 的共享互斥资源。

结果是在只有一个 E 槽的情况下同时提供两条 E 向发送服务，相当于 rematch 边界临时增加 ISL 容量。该问题直接污染时延、queueing 和 throughput，因此阻塞 D2 作为物理拓扑模型使用。

F3 — major — 退役链路从不回收，动态创建链路绕过 max_entities

FACT

max_entities 只在 Kernel 初始化创建初始 ISL 时计算并检查。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L827-L838

每次 peer 改变都会把旧对象追加到 _retired_isls，同时创建新的 ISLLink；这里没有 entity 计数或 max_entities 检查。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L956-L980

每个 ISLLink 构造都会启动永久 _run() process。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L559-L589

允许范围内对 _retired_isls 的完整审阅只看到初始化、追加和 _all_isls() 聚合，没有回收路径。

INFERENCE / reproduction condition

配置短 recompute_interval_s，并让一个或多个方向持续改变 peer。每轮都会积累 retired object/process；长时窗正是 D2 的目标场景，因此可以超过原有 max_entities 所声称的界限并持续增加内存/SimPy process 数。

F4 — major — rematch 后仍在旧链路服务的数据/控制状态会从 Q0 全局快照中消失

FACT

设计允许 rematch 边界的在服包继续完成旧链路服务。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L64-L70

实现随后把旧对象放入 _retired_isls，并用新对象替换 self.isls[s][direction]。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L956-L980

但是 snapshot_global() 构造 isl_links 时只遍历当前 self.isls。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L1058-L1085

Q0 的 _data_packet_locations() 同样只遍历当前 self.isls，而不是 _all_isls()。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/kernel.py#L1200-L1245

INFERENCE / reproduction condition

让数据包的 ISL service 跨越 rematch 边界。rematch 后、旧 service 完成前，该包仍真实存在于 retired link 的 current 中，但尚未进入 _in_flight propagation；此时 snapshot 和 Q0 location index 都看不到该包。

这与 snapshot 声称的 CURRENT-state 全局状态不一致，会造成动态拓扑开启后的状态完整性回归。

F5 — major — 实现的跨面候选集合比设计合同更窄

FACT

设计写的是：候选边只要求 a,b 属于“不同面”、当前 isl_available，并满足 E/W 槽约束。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L40-L48

实际 _cross_plane_matching() 只枚举：

east_plane = (p + 1) % num_planes

即仅考虑环上立即相邻的东侧 plane。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/model.py#L543-L569

物理合法性过滤本身确实调用 isl_available()，这一部分正确。
证据：github://fuguther/leo-direct-sim/blob/0cff2547c59ca2d8f66d690f6b922d6bf71588b9/CODE/leo_sim/model.py#L550-L560

INFERENCE / reproduction condition

当 num_planes > 3 且存在一个可用、距离更短的非相邻-plane 跨面候选时，设计规则会让它进入全局 greedy 排序，而当前实现永远不会枚举它。

若设计中的“不同面”确实是字面合同，则 matching semantics 不符合 D2；如果项目实际意图是“仅相邻 plane”，需要先修改设计合同并补对应测试，而不能继续声称当前实现等价于该设计。
