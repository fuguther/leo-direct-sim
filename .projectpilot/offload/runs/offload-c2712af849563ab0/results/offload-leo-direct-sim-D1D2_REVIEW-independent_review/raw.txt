D1/D2 independent cold-start review

Verdict: REQUEST_CHANGES

结论为 RESULT_CANDIDATE。基于 commit 2bf385870a06c2aa710cca93b528809b10f9c05e 的只读静态审阅，我认为该 combined baseline 目前不满足 D1/D2 合同级验收。发现 4 个 major：D1 零速率恢复被 time_step 轮询量化；D2 真实 Markovian matcher 在合法方向/单平面边界上违反设计；D2 rematch 与 learning forward transition 不兼容；constant rate mode 仍强制依赖 RF/MCS 配置，违反“constant 忽略 RF”的合同。另有明显测试覆盖缺口。

受任务约束，我没有执行本地测试或 Shell；下面的 FACT 来自 pinned commit 的允许路径，运行时后果在未执行时明确标为 INFERENCE。

Findings
F1 — major — D1 零速率恢复没有统一使用认证 crossing，GSL/新 ISL 决策可能延迟到下一 time_step

FACT。 D1 设计明确要求：低于 MCS 门限时应当像链路 down 一样，通过 next_slant_range_under / next_isl_range_under 找到认证恢复时刻，并与 deadline/硬退役竞速；服务应在真正可用时开始，而不是用 dur=∞ 或粗粒度等待。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/ANALYSIS/LINK-BUDGET-DESIGN-20260816.md#L47-L78

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L1470-L1645

_transmit 本身实现了这一精确恢复机制；但调用链在进入 _transmit 之前又增加了零速率过滤：

Uplink _pick() 在 MCS rate <=0 时直接返回 None；整个 uplink server 随后只按 time_step 轮询。认证 next_slant_range_under 只有包已经成功被挑出后才会传给 _transmit。

Downlink _servable() 同样先拒绝零速率包，再以 time_step 轮询。

新到 satellite 的 ISL 数据包在 _decide() 中遇到 MCS rate <=0 会被放入 pending；而 pending 只由 _pending_ticker() 每个 time_step 重决策。只有已经进入 ISL 队列的包才由 ISLLink._run() 使用 next_isl_range_under 精确等待。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L500-L570

F2 — major — D2 真实 _cross_plane_matching 不满足允许配置下的 E/W matching 合同

FACT。 配置接受任意非空 isl_dirs ⊆ {N,S,E,W}；设计要求动态 rematch 对“跨面 E/W 候选”进行贪心匹配，候选必须来自不同 plane。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/config.py#L528-L555

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/ANALYSIS/TOPOLOGY-REMATCH-DESIGN-20260819.md#L25-L55

实际 matcher 有两个边界缺陷：

_cross_plane_matching() 的 plane 循环开头是 if "E" not in dirs: break。因此合法的 isl_dirs=["W"] 会直接产生空 cross-plane matching，尽管 neighbors_at() 明确在 W 被请求时调用 matcher。

east_plane = (p + 1) % num_planes 没有检查 east_plane != p。因此 num_planes=1 时会在同一 plane 内生成所谓 E/W “cross-plane”候选，违反设计的“不同面”前提。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/model.py#L557-L608

routing.build_topology() 的双向验证不能发现 “W 被静默省略” 的情况，因为空 edge set 会 vacuously pass。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/routing.py#L55-L82

INFERENCE。 对 W-only dynamic configuration，启用 recompute 会把预期的 W 跨面连接静默消失；对单 plane built-in geometry，可能生成错误类别的同面 E/W link。两者都会改变 reachability、控制树与后续 packet fate。

现有 D2 测试并未调用真实 Constellation._cross_plane_matching；它们全部通过 StaticGeometry(..., neighbors_at_fn=at) 注入预制 topology，因此无法捕获 matcher 本体错误。

Blocks baseline: YES. 这是 D2 核心拓扑生成语义本身的错误。

Required reproduction: 对真实 Constellation 增加 W-only、E/W、num_planes=1、num_planes>=2 的 matcher 测试；若 W-only/E-only 不应被支持，应在 config 层 fail-loud，而不能运行后静默改变 topology。

F3 — major — D2 rematch 回退 queued data 会留下未结算 learning forward transition，后续重决策可 fail-loud

FACT。 一个 learning forward action 被选中时，_learning_action() 将：

learning_state 设置为当前 state；

learning_action 设置为 forward direction；

learning_reward=None；

加入 _learning_open。

forward queue reward 只有等到 ISL 真正开始 transmission 时，_transmit() 才结算。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L1600-L1645

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L2199-L2235

D2 rematch 则会把旧 ISL data_q 中尚未开始 service 的数据包直接：

old data_q -> remove bits/area -> _hold_packet(s,pkt)

但没有关闭、取消或重新定义这个尚未实现 reward 的 forward transition。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L1054-L1094

而包下一次真正需要 learning redecision 时，_learning_action() 对任何

learning_state != None && learning_reward == None && learning_action != "deliver"

显式抛出 KernelError("unsettled non-deliver learning transition at re-decision")。

Evidence:

github://fuguther/leo-direct-sim/blob/2bf385870a06c2aa710cca93b528809b10f9c05e/CODE/leo_sim/kernel.py#L2199-L2220
