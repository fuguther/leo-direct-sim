# 循环控制器与材料清单（LOOP-CONTROLLER v1.0，2026-09-10）

> 用户指令（2026-09-10 对齐）：**并行最多 3 个主题**；**不局限于已有 9 卡**，可在 LEO 路由（时延/负载/到达率）小领域内自由选题；
> **直到至少 2 个很好的选题跑完整个流程，各个材料都按老师的准备全**；被刷掉的卡**必须保存理由**。

---

## 1. 终止条件（唯一的"可以收工"判据）

**当且仅当 ≥2 个主题同时满足下列全部条件**，本轮循环终止：

```
[合格] 该主题通过 G1–G5 全部闸门（无未消除致命项）
[完整] 该主题的"材料清单"（§4）全部齐备
[留痕] 该主题的审查记录、闸门判定表、must-address 回应、证据指针全部落盘
[对比] 与其余保留主题的取舍理由已写明（为何推荐这条/备选那条）
```

**不满足时的默认动作**：继续循环（§3），**不得**以"流程跑完""时间到了""文件齐全"收工。

---

## 2. 并行度与角色预算

| 阶段 | 并行上限 | 说明 |
|---|---|---|
| 生成 | **3**（= A/B/C 三轴，或按新轴重组） | 每次生成必须全新上下文、互不可见 |
| 深化 | **3** | 每主题一个子代理；超过 3 则排队 |
| 三角色审查 | **3/主题**（builder/neighbor/evidence 各一） | 但可跨主题排队，总投资受 §2 总量控制 |
| 历史审查 | 1（批量审当前池） | 每轮一次，审全部在池卡 |

**总循环轮次上限**：3 轮（与 `QUALITY-GATE-R2` §3 的"每卡 ≤3 轮"独立计算）。
3 轮后仍 <2 条合格 → 触发 `EXPLORATION-FALLBACK` §4 的**如实报告**流程。

---

## 3. 单轮循环（Round N）

```
3.1 生成（≤3 路，全新上下文）
      —— 若本轮是对上一轮的"轴扩展"或"提问类型转换"，在提示词中写明新轴，
         但**不得**把上一轮的候选身份/死因写进生成器提示词（只给论文事实）

3.2 初筛（主控）
      —— 去重、合并同题、登记 ledger（add）
      —— 必跑污染审计 audit_contamination4.py；违规 → 该批作废重跑

3.3 历史碰撞审查（独立子代理，1 个，审全池）
      —— 五类裁决 + must-address 清单

3.4 收窄（主控）
      —— 保留：裁决 ①②③ 且 G1 现象有原文锚点者
      —— 淘汰：裁决 ④ 且致命
      —— **每张被淘汰的卡都写淘汰记录**（类型 A/B/C + 依据 + 是否带复活条件）
         → ELIMINATED-REGISTER §6

3.5 死因回传（主控摘录）
      —— 为每张保留卡写 feedback/<卡ID>.md（仅本卡相关；禁历史全集）

3.6 深化（≤3 并行）
      —— 三问 + must-address 逐条回应 + 承重引文回原文

3.7 三角色审查（各新上下文）

3.8 闸门判定（主控填 GATE-TEMPLATE）
      —— 过 / 修订（≤3 轮）/ 淘汰（写理由）

3.9 若本轮结束时"合格主题数"仍 <2 → 进入 Round N+1（回到 3.1）

3.10 每次循环结束 → 更新台账、提交推送（每轮一个 checkpoint）
```

## 4. 单主题的完整材料清单（"按老师的准备全"）

一个主题要**能直接拿去给老师讲**，必须齐备以下材料。缺任何一项 → 该主题标记"材料不全"，不得计入 §1 的"合格"计数。

### 4.1 论证材料
- [ ] **三问完整回答**（每问须有：结论 + 证据 + 反方检查）
  - 问1：条件、具体方法、训练/部署设置、负载变化形式、影响到达率/时延的过程
  - 问2：原因辨析 → 对应手段 → **一次具体的决策或学习更新**（状态量/动作/目标函数/更新式）→ 失效条件
  - 问3：混合负载训练 / 在线微调 / 已有信息 / 规则路由 / 直接近邻，**对齐条件下**逐条比较
- [ ] **机制图**（Mermaid）：能走通一次决策 + 一次学习更新
- [ ] **承重证据表**：每条断言 → 论文（cite_key/itemKey）+ 节号/表号 + 原句摘录
- [ ] **反证与边界**：已知反例、适用边界、什么情况下本方案不成立

### 4.2 差异材料
- [ ] **最近邻清单**：最接近的 3–5 篇，逐篇写四要素差异（条件/困难/机制/决策变化）
- [ ] **直接对手核查记录**：Undermind `citing` 检索结果 + 结论（是否构成威胁）
- [ ] **查新记录**：patched_novelty 四态 + "未命中"的限定措辞

### 4.3 验证材料
- [ ] **验证设计**：实验矩阵（自变量/因变量/对照）、指标定义、seed 与重复次数、判定阈值
- [ ] **第一步行**（半天–两天）：具体做什么、看什么、什么结果算通过/淘汰
- [ ] **负结果预案**：若首步失败的下一步
- [ ] **基线清单**：每条基线为什么公平（信息/预算/条件对齐说明）

### 4.4 过程材料
- [ ] 闸门判定表（GATE-TEMPLATE 填写版，含每轮）
- [ ] must-address 逐条回应
- [ ] 审查意见与处置记录（采纳/驳回 + 理由）
- [ ] 台账版本链（cand_id → version → content_hash）

### 4.5 汇报材料
- [ ] **一页主报告**：问题、为何值得做、怎么做、与现有工作的差别、预期贡献
- [ ] **完整研究文稿**：场景 → 现有不足 → 原因 → 针对性改动 → 最近邻差异 → 验证设计
- [ ] **文献指引**：先读哪几篇、承重原文位置、阅读顺序建议
- [ ] **取舍记录**：比较过哪些实质不同的问题、什么证据改变判断、为何推荐这条

## 5. 淘汰记录规范（"被刷掉的也要保存理由"）

每张未通过的卡，在 `ELIMINATED-REGISTER.md` §6 追加一行，**必含**：

| 字段 | 内容 |
|---|---|
| cand_id + 标题 | 台账标识 |
| 淘汰类型 | A 证伪/覆盖 / B 流程中止 / C 合并吸收 |
| 淘汰阶段 | 哪一步被刷（初筛/历史审查/深化/闸门 Gx） |
| 依据 | 具体证据或裁决出处（**不得**只写"不够好"） |
| 是否带复活条件 | 若有，写明条件与判据 |
| 与保留主题的关系 | 是否被吸收进某条主线（资产去哪了） |

**禁止**：删除卡文件、清空台账、把淘汰理由写成"暂不考虑"。

## 6. 自我审计（每轮结束时问自己）

1. 本轮新增了**信息**，还是只是把同样的东西换了个说法？（后者 → 触发提问类型转换）
2. 有没有因为"想凑够 2 条"而放宽 G1–G5？（有 → 回退）
3. 被淘汰的卡，理由是否能被第三方复核？（不能 → 补证据）
4. 深化者是否只看过本卡反馈？（不是 → 该卡深化作废重跑）
5. 交付材料是否真能拿去讲给老师？（不能 → 对照 §4 补）
