## 2. 发现的问题与处置

### D-1（已修 + 回归）：空 content_hash 被接受 → 产生"永不过期的陈旧意见"
- **现象**：\`review-register\` 在不传 \`--verify-ledger\` 时，\`--content-hash ""\` 被静默接受（登记为 \`c0cd8adaad7@\`）。
- **后果**：\`invalidate()\` 按真实 hash 比对，空哈希意见**永远不会**被标 \`needs_review\`；即候选承重字段已改，旧意见仍显示 active——正是本项目最忌的"判断可信度"漏洞。
- **证据**：dry-run 中 DR1（空哈希）在 candid 承重变更后 status 仍为 active，而 DR2（正确哈希）正确变为 needs_review。
- **修复**：\`ledger.py\` review-register 增加格式校验（\`h?[0-9a-f]{8,}\`），空/畸形一律 exit 2。**回归 T13** 覆盖 5 种畸形输入 + 正确路径 + 失效触发。
- **验证**：空哈希 → \`REJECTED\`；正确哈希 → 登记成功且承重变更后被正确失效。套件 12/12 PASS。

### D-2（已修）：污染审计工具初版产生假阳性
- 初版对会话日志做全文关键词计数，把**我提示词里写的黑名单路径**算成违规，三个生成器全部被误判。
- 修复：改为解析 \`tool/call\` 事件并只检查**调用参数**（\`audit_contamination2.py\`）。教训：审计工具本身必须先自检，否则会制造假案。

### D-3（发现真实漏洞）：黑名单只禁"读文件"，未禁"列目录"
- 生成器C 执行 \`ls round/run1/\`，虽未读内容，但**目录列举泄漏了旧卡文件名**（\`card-F1-freshness.md\`、\`card-L1-lifetime.md\`、\`card-B3-window.md\`）——文件名本身携带旧候选身份。
- 处置：① 规则补"列目录"禁令（见 §4 待办）；② 后续 run 的卡文件改用无语义 ID（如 \`c-<hash>.md\`），从命名上消除泄漏面；③ 独立审计把 \`ls\`/\`find\`/\`glob\` 对黑名单目录的调用计入违规。

### D-4（已补模板）：质量闸门与死因反馈原先只有原则、没有承载文件
- 现象：G1–G5 与 must-address 写在规则里，但**没有模板**说明在哪里逐条判定、由谁签、附什么证据；实际操作易退化为口头判断。
- 处置：建立 \`round/run2/gates/\` 与 \`round/run2/feedback/\` 目录模板（见 §3）。

### D-5（未解，须真实轮次验证）：三路生成器尚未产出，端到端仍属"未通电"
- 三路生成器仍在运行（\`6dd5881f\`/\`b77deb91\`/\`4e787df3\`），staging 未落盘。
- **未经真实数据检验的环节**：初筛去重质量、历史审查五类裁决是否真能判死旧题、G1–G5 是否可操作（尤其 G4"简单办法是否足够"**在没有实验的情况下如何给出可信判断**）。
- 这三点只能在真实轮次暴露；本报告不宣称它们已验证。

### D-6（观察，非缺陷）：ledger \`add\` 硬编码初始状态 \`awaiting_evidence\`
- 新卡一律入 \`awaiting_evidence\`，无 \`--status\` 入口；若某卡初筛后应记 \`backlog\`，需二次 \`status\` 调用。
- 判定：可用但不够精确；不阻塞，登记为待改进项。
