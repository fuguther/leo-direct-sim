# Q0 信息裁剪与双向实验协议

> CURRENT；最后核验：2026-08-20。本文合并 Q0 研究目的、算法选型、接口与 tiny 验证要求；旧版 Q0 日期文档仅作 supporting evidence。

## 1. 研究问题

Q0 用来分解三个差距：

1. 网络在相同物理约束下还剩多少可优化空间；
2. 差距有多少来自信息不足；
3. 差距有多少来自决策/学习能力不足。

Q0 只放松调度器的信息与可选控制能力，不取消传播时延、有限速率/队列、链路竞争、接入槽、切换、几何失效或随机中断。

## 2. 三类参照必须分开

| 名称 | 信息 | 控制 | tiny 严格算法 | 能支持的 claim |
|---|---|---|---|---|
| Q0-F | 完整未来 trace/事件 | 按冻结控制合同 | 事件时间 MILP/CP-SAT | clairvoyant 数值上界、未来信息价值 |
| Q0-I | 当前全局真值，不知未来随机实现 | 固定现有服务策略或明确联合控制 | 事件驱动 SMDP/DP | 当前因果信息条件下最优参照 |
| Q0-J | 可与 Q0-I/F 组合 | 路由+WAIT+服务次序+接入分配 | tiny 联合调度 DP/MILP | 控制范围扩大带来的价值 |

普通时间扩展 min-cost flow 允许流体化、可分流或抢占时，只能作为乐观松弛或候选路径生成器。普通 MPC 是强基线，不自动成为严格上界。

## 3. 主线：从最优向下裁剪信息

理论主线使用嵌套信息集：

`Q0-F 完整未来` → `Q0-I 当前全局` → `去远端队列` → `去不可预测远端拓扑` → `只给陈旧/局部快照`。

在物理约束、动作集合和真正最优求解保持一致时，信息减少后的最优值不应更好。每一级下降表示“在仍保留其他信息的条件下”该信息的边际价值。

| 裁剪 | tiny 严格模型 | 大规模参照 | 解释限制 |
|---|---|---|---|
| Q0-F → Q0-I | clairvoyant MILP/CP-SAT → SMDP/DP | future rolling optimization → causal MPC | 差值是未来信息价值，不是当前全局信息价值 |
| 去远端队列 | 队列影响竞争时用 belief-state DP/POMDP | belief-MPC、本地队列+流量先验 | 经典 backpressure 缺相邻队列差后不再适用 |
| 去远端拓扑 | 可由轨道精确预测时算法族不变；随机不可见时 POMDP | 机会路由/分散策略 | 必须区分“不可直接观测”和“不可预测” |
| 去 AoI/历史 | 同陈旧度下 belief/robust DP | stale-state MPC、分散 RL | Q0 直读当前真值时 AoI=0；age 问题属于现实分散臂 |
| 三者叠加 | tiny belief DP | 因果滚动优化/分散 RL | 大规模通常只有强参照，不是严格界 |
| 再限制控制范围 | 固定 FIFO/DRR 的路径/时序 MILP | 同约束 MPC | 得到“仅路由类”上界，低于联合调度上界 |

一条链会受裁剪顺序影响，因此至少保留三类一刀消融、关键两刀组合和全裁剪端点。组合的目的不是穷举所有 `2^k`，而是检查主要交互。

## 4. 辅线：从现实向上增加信息

工程辅线固定同一实践算法和训练预算：

`本地队列+方向` → `+速率/可用性` → `+远端队列/拓扑` → `+逐字段 AoI`。

它回答“当前可实现系统先增加什么最划算”，但结果混入表征、容量、训练和优化误差，不能替代理论信息上界。相同信息节点应与主线对齐：

- Q0-I 最优 vs 局部信息最优：信息差距；
- 局部信息最优 vs 当前 GAT/DDQN：决策/训练差距；
- Q0-F vs Q0-I：未来信息差距。

## 5. 建议目标函数与待冻结控制合同

以下是当前推荐合同，不是已批准实现事实；R6-F1/R6-F3 关闭前仍为 open。建议主目标使用物理字典序：

1. 最大化 deadline 前交付 bits/packets；无 deadline 时最大化完成量；
2. 最小化未完成与队列积分；
3. 最小化完成包端到端时延及尾部。

学习奖励只作训练信号，不能作为 Q0 最优性定义。每个实验必须声明：

- 是否允许预测确定性轨道/几何；
- 是否知道未来 traffic、GE 或拓扑随机实现；
- deadline 同时刻语义；
- 是否固定 FIFO/DRR/forced-deliver；
- 是否允许 WAIT、服务顺序和 access assignment。

## 6. 接口与执行证据

- `snapshot_global()`：同一仿真时刻的不可变当前状态，不推进事件，不读取未授权未来。
- `JointPlan`：绑定 snapshot version；整份只读校验后原子提交；过期、超容量、非邻接或所有权错误均整份拒绝。
- WAIT：进入有限 holding queue，计容量、queue area、deadline 和 overflow fate。
- `action_id`：必须从计划贯穿排队、服务、传播和交付事件，不能靠时间/签名猜测。
- receipt：持久化 planned、executed、verdict、errors、first divergence 和 replay hash。

## 7. tiny 验收

1. 同一 2–3 星、少量包场景由独立穷举或第二实现求解。
2. Q0-I DP 与独立解逐动作、目标值一致。
3. Q0-F MILP/CP-SAT 与可枚举实例一致，并验证 `V_F >= V_I`。
4. 计划注入 kernel 后逐事件 replay；任何瞬移、FIFO 绕过、非原子部分执行或归因歧义 fail-loud。
5. 对未来 arrival、随机中断和控制权限分别做负测试，证明信息边界不是口头约定。
