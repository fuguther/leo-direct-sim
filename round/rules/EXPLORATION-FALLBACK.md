# 探索继续与失败升级协议（EXPLORATION-FALLBACK v1.0，2026-09-10）

> 回答的问题：**如果本轮 9 张卡全部不通过，下一步怎么继续探索？** 以及每一级失败意味着什么、该做什么、何时该停。
> 前置：`QUALITY-GATE-R3.md`（G1–G5 闸门）、`EFFECTIVE-RULES-R2.md` §8（流水线）、`ELIMINATED-REGISTER.md`（淘汰台账）。

## 1. 先做失败归因，而不是"再试一次"

9 张卡死后，**第一件事是分类死因**，不是立刻重跑：

| 死因分布 | 含义 | 下一步 |
|---|---|---|
| >60% 死在 **G1（现象不成立）** | 我们对语料的阅读深度不够，"空白"判断草率 | 不做新一轮生成；先补**证据地基**（§3.1 缺口挖掘） |
| >60% 死在 **G2（原因无依据）** | 机制是猜的，缺少可观测中间量 | 转入**测量/表征型**提问（§4.5） |
| >60% 死在 **G4（简单办法已足够）** | 该子方向已被成熟方法覆盖 | **不要再做"改进方法"**；转做**边界条件/归因分离**型（§4.2/4.4） |
| >60% 死在 **G5（撞直接对手）** | 方向已成熟或我们查新不足 | 先跑**引用网络查新**（Undermind `citing`/`referenced`，§3.2），再决定 |
| 死因分散 | 属正常筛选损耗 | 按 §3 系统性扩展后重生成 |

**关键**：死因分布本身就是情报。它告诉我们"这个方向缺的是什么"，而不是"这个方向不行"。

## 2. 三级升级阶梯

```
① 同轴重生成（换角度/换提问类型）
      ↓ 仍全灭
② 轴扩展（负载变化的其他切面）+ 证据地基补强
      ↓ 仍全灭
③ 提问类型转换（从"改进方法"转向"测量/边界/归因/反例/协议"）
      ↓ 仍全灭
④ 停止并向用户报告（不是"流程完成"）
```

每一级都必须**先补证据、后生成**——重复生成而不增加信息，只是烧预算。

## 3. 系统性扩展手段（每一级都用得上）

### 3.1 证据地基：从 111 篇里挖"作者自己说的缺口"
程序化扫描全部 MinerU MD，抽取：
- **Limitations / Future work / 未做** 段落（`future work`、`left for future`、`we do not`、`beyond the scope`、`not considered`、`remains open`）；
- **未解释数字**：表格中与正文叙述不一致、或只报一项指标的组合；
- **矛盾结论**：不同论文在相近条件下给出相反结论（如"队列感知有效"vs"队列感知无增益"）——这类矛盾是**最有价值的问题源**；
- **复现缺口**：无 seed、无超参、无代码、无流量模型说明。
产出：`round/evidence/GAP-MAP.md`（按轴分类的缺口清单 + 出处）。**这是下一轮生成的白名单输入**（是论文事实，不是候选）。

### 3.2 引用网络查新（Undermind `citing`/`referenced`）
见 `UNDERMIND-PLAYBOOK.md` §5.2。对 5–10 篇关键工作跑：
- `citing` → "谁在做同一件事"（找对手）
- `referenced` → "这条路从哪来"（找奠基与边界）
产出：`round/evidence/COMPETITOR-MAP.md`（直接对手 + 差异四要素）。

### 3.3 死卡反哺（**不违反隔离**的正确做法）
死卡不能直接喂给下一轮生成器（会污染）。正确做法是**把死卡在深化中获得的新论文事实，蒸馏成中性证据条目**，写进 `round/knowledge/notes-neutral/`（统一格式、带 itemKey/节号），再作为白名单进入下一轮。
- 允许回流：**论文事实**（"某文报告 X 条件下降解 Y%"）；
- 禁止回流：**候选身份与死因**（"我们试过 Z 方向，因为…被淘汰"）。
这条边界是"知识复利"与"污染"的分界线。

### 3.4 轴扩展清单（负载变化方向内，尚未探索的切面）
| # | 切面 | 与已探索 A/B/C 的区别 |
|---|---|---|
| 1 | 负载的**空间相关性**变化（热点是否成片 vs 独立散点） | B 只变了热点位置，未变相关结构 |
| 2 | **需求方向性**变化（上/下行不对称、多对一汇聚 vs 一对多分发） | A/B/C 都是对称 OD |
| 3 | **多时间尺度叠加**（昼夜 + 突发 + 闪聚同时发生） | C 只扫单一突发参数 |
| 4 | 负载变化与**拓扑运动的耦合/解耦**（热点随星动 vs 逆星动） | B 隐含热点相对地面固定 |
| 5 | **接入段/GSL** 在负载变化下的瓶颈转移 | A/B/C 都聚焦 ISL |
| 6 | 负载变化的**可预测性谱**（完全随机 → 完全可预报 → 部分可预报） | 新维度：可预测性本身作为自变量 |
| 7 | 负载变化下**控制面/信令**的容量竞争 | A3/B2 沾边但未系统化 |
| 8 | **多运营商/多域**负载边界（跨域流量在负载变化时的行为） | 历史 A 类曾判"已覆盖"，但那是静态口径 |

### 3.5 提问类型转换（当"改进方法"走不通时）
| 类型 | 提问形式 | 何时用 |
|---|---|---|
| 测量/表征 | "X 在 Y 条件下的真实分布是什么？"（无人测过） | G2 集中死 |
| 边界条件 | "X 在什么条件下开始失效？" | G4 集中死 |
| 归因分离 | "退化由 A 还是 B 主导？如何分离？" | 现象成立但原因争议 |
| 反例构造 | "被广泛接受的声称 Y，是否存在反例？" | 有强势共识时 |
| 协议/评估 | "如何构造一个能分离三假说的评估协议？" | 全领域都在自评时 |
| 负面结果 | "为什么简单方法就够了？" | G4 集中死时**反用** |

## 4. 停止条件与如实报告

达到以下任一条，**停止生成**并向用户交付结构化报告：
1. 三级阶梯走完（≤3 轮），无卡通过 G1–G5；
2. 关键信息不可得（付费墙/数据不公开）且无法替代——导致 G1 无法判定；
3. 连续两轮的死因分布相同且无改善（说明补证据的手段已用尽）。

**报告必须含**（不得写成"流程完成"）：
- 卡在哪一段论证（G1–G5 逐条证据）；
- 已排除什么（哪些轴/类型被证伪或覆盖）；
- **下一项什么信息可能改变决定**（具体到论文/数据/实验，且说明为什么它能改变）；
- 剩余预算与建议（继续、换方向、还是向用户索取资源如付费文献/VM 数据）。

## 5. 与用户交互的升级点

出现以下情况**立即问用户**，不自行决定：
- 需要付费文献/私有数据才能过 G1；
- 需要启动训练/仿真（超出本轮授权）；
- 三级阶梯走完仍无合格主线（交付 §4 报告）；
- 发现方向本身可能不成立（例如整条 A 轴的"空白"被一篇新论文填上）。

## 6. 本轮适用（9 卡在途）

9 卡正处在历史审查 → 深化 → 闸门流程中。若结果不佳，按本文件 §1 归因 → §2 阶梯执行；**不因为一张卡失败就推翻"负载变化"方向**（用户明确要求），也不靠改名/加条件/补风险声明维持推荐。
