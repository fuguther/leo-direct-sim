F1 — retiring uplink 仍绕过 availability gates

严重度：blocking

FACT

UplinkServer._pick() 首先允许 active 和 retiring link；但进入 packet loop 后：

retiring 分支只检查 p.assigned_sat == self.sat，随后直接 return p；

geometry、GSL GE 和 MCS rate 三个 gate 只存在于后面的 active elif 分支。

证据：

github://fuguther/leo-direct-sim/blob/026eb17cd41a2645ab58ae1b8fd0e256f1f19cb1/CODE/leo_sim/kernel.py#L273-L296

一旦 _pick() 返回 packet，uplink server 会把它从 endpoint queue 移除、减少 queued_bits/queue-area，并转入 _transmit()：

github://fuguther/leo-direct-sim/blob/026eb17cd41a2645ab58ae1b8fd0e256f1f19cb1/CODE/leo_sim/kernel.py#L298-L339

_transmit() 本身确实会重新检查 geometry/GE/rate，并在不可用时等待 recovery/deadline/retirement：

github://fuguther/leo-direct-sim/blob/026eb17cd41a2645ab58ae1b8fd0e256f1f19cb1/CODE/leo_sim/kernel.py#L1270-L1365

INFERENCE / concrete reproduction

构造：

MBB old uplink 已进入 retiring，且 now < retire_at；

endpoint queue head 的 assigned_sat == old_sat；

此刻满足任一个条件：

GSL geometry unavailable；

GSL GE down；

MCS rate = 0。

同一 satellite uplink server 还有其他 endpoint 可以服务。

结果：

_pick() 会在 retiring 分支直接选择该包，绕过 availability gates。包被 dequeue 后才在 _transmit() 中等待。这会：

阻碍其他 endpoint 的 DRR service；

在尚未真正 transmission start 的等待期间把 packet 从 endpoint queued-area 中拿走。

因此 round-2 F1 的核心问题仍然存在。

作为对照，downlink _servable() 对 retiring link 并没有这个特殊绕过：通过 state/retire deadline 后仍统一检查 geometry、GE、MCS rate。

github://fuguther/leo-direct-sim/blob/026eb17cd41a2645ab58ae1b8fd0e256f1f19cb1/CODE/leo_sim/kernel.py#L430-L444
