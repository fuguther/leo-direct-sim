## 2. 派发前必做（三次探针，缺一不可）

```
1) 最小探针：子代理只回一行文字（不发工具调用）→ 确认路线活着
2) 能力探针：让子代理做一次真实小任务（读一个白名单文件 + 回一行摘要）→ 确认工具可用
3) 配额探针：连续 2 次调用，确认非"首调用成功、次调用 403"
```
**任一步失败 → 换 P1/P2 中的下一条可用路线，并在 DISPATCH-RECORD 留痕。**

## 3. 禁止事项（硬约束）

1. **禁止静默降级**：路线切换必须在 `round/dispatch/DISPATCH-RECORD.md` 写明「原路线 / 失败原文 / 新路线 / 切换理由」；
2. **禁止启用用户禁用路线**（v4-flash），即使配额紧张；
3. **禁止把配额错误当任务失败**：403 quota 是**环境故障**，不是"任务做不出来"——须报告用户而非猜测任务本身；
4. **禁止在同一批次混用不同路线**（除用户明确要求），避免能力差异污染 A/B/C 三路可比性；
5. 长任务（>30 min）派发前，确认路线**不在配额窗口边缘**（本轮教训：18:02 刷新后 4 小时内耗尽）。

## 4. 失败取证（五步法，本轮已实践）

1. 记录退出码/错误原文；
2. 读真实日志——**子会话日志** `~/.dsh/sessions/<proj>/<subagentId>/session.jsonl.zstd`（`zstd -dc` 解压看 turn/end）；
3. 最小复现（最小探针）；
4. 分类：环境（配额/网络）/ 模型（能力）/ 权限（白名单）/ 配置；
5. 输出「事实 + 证据 + 结论」。

**本轮实例**：三个生成器状态 `ready` 无产物 → 解压子会话日志 → `turn/end reason: AUTH 403 quota` → 结论=配额耗尽（非任务问题）→ 换 GLM 重派成功。
