# Hook 命名规则（HOOK-NAMING-RULE，主控，2026-09-11）

## 实测结论：受控路径下的文件名必须只用 ASCII

**复现证据**（主控在 worktree 内直接跑 hook 库判定）：
- guard 从工具参数里用正则 `[A-Za-z0-9_./\-]*\.(?:md|csv|json|pdf|txt|py)\b` 提取候选路径；
- 该字符类**只含 ASCII 连字符**，不含 en-dash（U+2013）/ em-dash（U+2014）/ 中文标点；
- 于是文件名 `LJG6ZW7B-L1–1200.md`（含 en-dash）被截取为 **`1200.md`**，与授权名不匹配 → 判定越权 → BLOCK。
- 换成 `LJG6ZW7B-part1.md` 后同一命令判定为**允许**（已实测）。

## 规则
1. **文件名、目录名一律 ASCII**：只使用 `A-Za-z0-9_-. `；不要用 –、—、"、"、《》等。
2. **中文内容放文件正文，不放文件名**。
3. 派发任务书里给出的输出文件名，必须是**与 grant 完全一致的字符串**（大小写、连字符类型都要一致）。
4. 若子代理报"角色不允许访问（shell-file）"而授权记录看起来正常，**先怀疑文件名含有非 ASCII 字符**，而不是怀疑子代理操作错误。

## 适用面
本条同时解释了两类此前的疑似异常：
- "同一文件 read 工具能读、bash 却报权限"——read 工具走结构化路径参数（不经过正则截取），bash 走字面量截取；
- "授权已给但仍被拦"——授权名与实际解析名不一致。
