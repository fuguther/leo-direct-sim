# Agent 文档治理设计

## 目标

让进入仓库的 Agent 能在一分钟内确定：哪些文件可以指导当前工作，哪些文件只提供证据，哪些内容已经被替代，以及哪些外部状态必须实时复核。旧资料继续保留可追溯性，但不得再凭文件名、日期或旧结论自动获得现行权威。

## 已确认的问题

1. `AGENTS.md` 末尾把 `NOTES.md` 指作当前状态入口，但 `NOTES.md` 自己声明只是滚动记录。
2. `AGENTS.md` 仍把已标记为 supporting 的迁移清单写成现行迁移取舍依据。
3. `README.md` 把 2026-08-14 的路由信息年龄目录描述为当前科研线。
4. 现行合同、易变状态、历史报告、旧实验矩阵和不可变证据产物共处一层；Agent 容易把旧 SHA、旧 VM 状态或旧实验结论当成当前事实。
5. 当前只有自然语言路由说明，没有机器检查来阻止新增文件漏登记或旧入口重新出现。

## 方案选择

采用“非破坏性隔离优先，物理归档后置”的混合方案。

- 不采用立即移动或删除：这会破坏大量交叉引用，而且按仓库规则需要逐路径批准。
- 不只增加零散警告：Agent 可能跳过某一条说明，无法保证新文件继续受治理。
- 先建立唯一入口、机器状态表、关键文档醒目标记和自动检查；完成后再根据引用关系提出精确归档清单。

## 权威层级

发生冲突时按以下顺序处理：

1. 当前 checkout 的代码、配置 schema、测试和可重算 receipt 决定实际行为。
2. `CURRENT-CONTRACT` 文档决定现行研究定义、实验合同和治理规则。
3. `CURRENT-VOLATILE` 文档只提供最近一次状态快照；其中的 branch、SHA、PR、CI、VM、run 和时间估计必须实时复核。
4. `SUPPORTING` 文档提供设计理由、方法、旧平台证据或诊断细节，不得覆盖现行合同和状态。
5. `HISTORICAL`、`SUPERSEDED` 和 `EVIDENCE-SNAPSHOT` 只回答“当时发生过什么”，不得据此安排当前下一步或宣称当前结论。

任何层级都不能把本地测试通过自动升级成已审阅、已合入、已部署、已授权或论文可用。

## 组成部分

### 1. 唯一 Agent 入口

新增根目录 `AGENT-START-HERE.md`。`AGENTS.md` 要求所有研究、实验、平台修改和审阅任务先读该文件。入口提供最短阅读顺序、权威层级、冲突处理和实时复核规则。

`AGENTS.md` 属于稳定的“宪法层”，不是项目状态页。本次只增加稳定入口规则，并修正已经确认的错误指向；日期、SHA、PR、VM、实验进度、文档复核日期和归档候选一律不得写入该文件。后续正常推进只更新状态表和对应事实文档，不修改 `AGENTS.md`。状态表保存其受保护内容哈希，未同步经过明确设计决策的改动会被检查器拦截。

### 2. 机器可读状态表

新增 `ANALYSIS/DOCUMENT-STATUS.json`，登记高风险指导文档和目录规则。每条记录至少包含：

- 路径或 glob；
- 状态；
- 用途；
- 可否决定当前下一步；
- 替代文档或实时复核要求；
- 最近复核日期和复核周期；
- 负责更新的文档角色。

状态固定为：

- `CURRENT-CONTRACT`
- `CURRENT-VOLATILE`
- `SUPPORTING`
- `ROLLING-LOG`
- `EVIDENCE-SNAPSHOT`
- `HISTORICAL`
- `SUPERSEDED`

### 3. 入口修正

修改以下文件：

- `AGENTS.md`：加入强制入口；把迁移取舍指向当前能力账本；把当前状态入口改成 `AGENT-START-HERE.md`。
- `README.md`：将 `ANALYSIS/` 描述改为文档治理入口、现行合同和历史证据区。
- `ANALYSIS/README.md`：以状态表为准，解释稳定合同与易变状态的区别。
- `EXPERIMENTS/README.md`：明确 `EXP-*` 是逐 revision 不可变证据，不代表当前有效授权或执行状态。
- `CODE/work/README.md`：明确旧 `WP-*` 只绑定各自 revision，不是当前工作指令。

### 4. 高风险旧文档隔离

为以下最容易被误用的内容增加文件内醒目标记：

- 2026-08-19 旧实验就绪路线图；
- 2026-08-17/18 Q0 算法稿和接口草案；
- 2026-08-14 路由观测/年龄目录中的旧实验计划、矩阵、配置、运行状态和结果；
- morning/overnight、handoff、implementation、旧任务书和旧 repo plan；
- 旧迁移与旧平台差距账本。

标记只改变文档解释权，不改写其历史正文和数值。

### 5. 易变状态边界

`CURRENT-EXPERIMENT-READINESS.md`、`PLATFORM-CAPABILITY-LEDGER.md` 和 `EXPERIMENT-PROGRAM.md` 可以继续承担当前路线与合同，但文件内出现的 SHA、部署、运行中/已完成、PR、CI 和时间估计都视为带核验时间的快照。Agent 在据此执行外部动作前必须检查当前 checkout、GitHub 和 VM。

### 6. 自动检查

新增文档治理测试，至少检查：

1. 状态表 JSON 可解析，状态值在固定集合内；
2. 每个登记的精确路径真实存在；
3. 高风险旧文档均已登记；
4. `AGENTS.md` 引用唯一入口，不再把 `NOTES.md` 或旧迁移清单当当前真相源；
5. `README.md` 不再把旧路由观测目录描述成当前科研线；
6. `SUPERSEDED` 文档在文件开头包含醒目标记和替代入口；
7. `AGENTS.md` 与状态表登记的受保护内容哈希一致，普通状态更新不得顺手修改它。

测试只管理指导和记录文档，不把全部运行配置、schema、原始实验产物或文献条目误归为项目指导。

### 7. 持续治理

治理不能依赖某次人工大扫除，使用同一个确定性检查器覆盖三个时机：

1. **每次 PR**：CI 检查新增或修改的项目指导/记录文档是否已登记，入口是否回退，替代链接是否存在。漏登记直接失败。
2. **每次 Agent 开工**：`AGENT-START-HERE.md` 要求先运行检查器；如果易变文档过期，Agent 必须先实时核对或明确标成未验证，不能沿旧状态继续执行。
3. **每周定时检查**：GitHub Actions 运行时效审计。`CURRENT-VOLATILE` 使用短周期，稳定合同使用较长周期；过期时生成检查失败和可下载报告，提醒下一次维护，不自动改写科研结论。

检查器可以生成“建议降级状态”“缺少替代入口”和“物理归档候选”报告，但不得自动移动、删除或改写已跟踪文件。文档的最合适位置由状态与用途决定：现行入口留在稳定路径；历史快照进入 `HISTORY` 候选；生成证据留在原 revision 目录。实际移动仍按逐路径批准执行。

## 物理归档边界

本阶段不删除、不移动、不改名任何已跟踪路径。状态隔离完成后，根据真实反向引用生成候选清单；只有“无现行入口依赖、移动后引用可完整修复”的路径才进入候选。执行移动前逐条列出源路径、目标路径和受影响引用，等待用户批准。

## 验收标准

1. 新 Agent 只读 `AGENTS.md` 和唯一入口即可找到当前合同与状态边界。
2. 旧 Q0、旧负载矩阵、旧路由年龄实验和旧运行报告不能再被解释为当前计划。
3. SHA、PR、VM、CI 和运行进度不会仅因出现在 `CURRENT` 文档里就被当成实时事实。
4. 自动测试能拦截关键入口回退、漏登记和缺失替代链接。
5. PR、Agent 开工和每周定时任务复用同一个检查器，不形成三套不同规则。
6. 过期状态会 fail-loud 并生成报告，但不会被脚本自动改写成未经核验的新事实。
7. 本阶段没有文件移动、删除或历史数值改写。
8. 本次完成后，正常实验推进和周期复核无需再次修改 `AGENTS.md`。

## 非目标

- 不在本次 PR 更新实验结果或替旧运行补结论。
- 不修改仿真内核、实验配置、授权产物或治理 schema。
- 不把历史证据从 Git 历史中清除。
- 不因为文档标成 supporting 就否定其中已核验的方法或历史事实。
- 不让定时任务自动提交、开 PR、移动文件或替人判断科研结论。
