# 旧平台 vs 新平台：通俗版对照

> 这是给「不想翻代码」的读者看的版本。详细的、每条带代码行号的版本在
> `03-platform-diff-detailed-kimi.md`。这里只讲清楚两套系统分别是怎么干活的、差别在哪。
> 只说差别，不说哪个更好。

## 一句话概括

- **旧平台**：一个 1.2 万行的大程序，流量从**地面网关**汇聚后上星，多年研究里不断往上加功能（好几种强化学习算法、联邦学习、各种观测方式），像一个不断加建的老楼。
- **新平台**：重新盖的 7000 行模块化系统，流量从地面**直接上星**（没有网关这个角色），每个模块只管一件事，每次运行留一份可以逐字段核验的「回执」，像按图纸建的新厂房。

## 最核心的五个差别

**1. 包裹从哪上车：网关中转 vs 卫星直销。**
旧平台里，用户流量先到地面网关（Gateway），网关再把数据包交给卫星网络。新平台里不存在网关，地面端点（TrafficEndpoint）直接把包发给头顶上的卫星。这是两套系统数据路径的根本差别，其它差别很多由此而来。

**2. 需求怎么产生：边跑边摇骰子 vs 先封箱再跑。**
旧平台在仿真运行时按「网关间流量矩阵」实时决定发包。新平台先把整段需求离线编译成一份**不可变的包裹清单**（每个包的 ID、出生时间、起点、终点、大小都写死），附一个防篡改的「指纹」（SHA-256）；仿真只准照单执行。好处是同一份清单可以喂给新旧两套系统做公平对照——新平台自带的 `comparison` 工具就是这么干的。

**3. 配置怎么给：一把环境变量 vs 一份带校验的 YAML。**
旧平台的开关散落在约 40 个环境变量和一个 `inputRL.csv` 里。新平台用一份 YAML 配置，有完整的字段白名单和合法性检查，写错字段直接拒绝启动。

**4. 出了事谁记账：事后翻日志 vs 当场记生死账。**
旧平台把数据包的遭遇写进日志文件，跑完再汇总审计。新平台在内核里放了两本**实时账本**：每个数据包有且只有一个结局（送达/丢失/超时…），控制包另有一本账，比特数必须守恒，跑完后还有一个独立的「回执验证器」把整份产物逐字段重算一遍，任何字段被改过都拒绝验收。

**5. 工具箱：研究杂货铺 vs 精简标准件。**
旧平台塞着多年积累的研究工具：Q 表学习、DDQN（十几种状态编码变体）、MAPPO、path-credit、TD(λ)、时序 GRU、联邦学习/CKA 分析、监控仪表盘……其中一部分经全库检索确认已无人调用（死代码），还有几处引用了当前工作区里已不存在的 `legacy/` 包。新平台只保留一套标准实现：四种路由策略（其中 oracle 被强制标注为「分析上界」）+ 一套规范的双 DQN（可选图注意力编码器），学习体能看到什么信息由明确的「合同」（C1/C3–C7）规定。

## 简化对照表

| 方面 | 旧平台 | 新平台 |
|---|---|---|
| 体量 | 17257 行，一个 12556 行的主文件 | 7116 行，19 个模块 |
| 数据路径 | 网关汇聚 → 卫星 → 网关 | 地面端点直连卫星 |
| 需求 | 运行时按 OD 矩阵生成 | 先编译成不可变 trace（带指纹） |
| 配置 | 环境变量 + CSV | YAML + 白名单校验 |
| 仿真边界 | 无统一事件上限 | 实体/包数/事件数都有硬顶，超顶即停 |
| 队列 | 软阈值（超过 5000 视为「无穷」） | 硬容量，溢出记为包的一种结局 |
| 链路中断 | 按调度表定时上下线 | 几何失效 + Gilbert-Elliott 随机两态模型 |
| 随机数 | 一个全局种子管所有 | 按用途分多条独立随机流 |
| 信息可见性 | 观测函数里隐式加延迟 | 显式控制包 + 缓存 + 有效期，合同化 |
| 结局账本 | 日志 + 事后审计 | 实时双账本 + 位守恒 |
| 验收 | 无包内工具 | 自带回执核验、场景验收、新旧双臂对照、平台自检 |
| 学习算法 | DDQN 家族 + MAPPO + 路径信用 + 联邦学习等 | 一套 canonical Double-DQN（可选 GAT/MPNN 编码器） |
| 已知包袱 | 若干死代码、3 处引用不存在的 legacy 包、若干 docstring 与实现不一致 | 少量工具函数仅被测试调用，无缺失依赖 |

## 读这份对照时要注意

- 「旧平台有 X、新平台没有」或反过来，都只是**存在性事实**，不代表 X 该保留还是该淘汰——那是主脑的终判范围。
- 表中的死代码、缺失依赖、docstring 不一致等，全部来自逐行通读（详见说明书 `02-kimi-platform-spec.md` 的「未确认」与「不一致」清单），不是评价，是记录。
